1.1 The Paging Concept: Pages, Frames & Hardware Mapping

Contiguous memory allocation suffers from fatal external fragmentation and requires expensive compaction. Paging completely eliminates external fragmentation by allowing a process's physical memory to be completely non-contiguous.

Fundamental Definitions: Pages vs. Frames

  • Frames: Physical memory (RAM) is broken into fixed-sized blocks called Frames (typically powers of 2, between 512 bytes and 16 KB; standard is 4 KB).
  • Pages: Logical memory (the process address space) is broken into blocks of the exact same fixed size called Pages.

Hardware Address Translation Architecture:

Every logical address generated by the CPU is divided by hardware bitmasking into two components: $$\mathbf{\text{Logical Address } = \langle \text{Page Number } p, \text{ Offset } d \rangle}$$ If the total logical address space is \(2^m\) bytes and page size is \(2^n\) bytes:

  • High-order \(m - n\) bits represent the Page Number (\(p\)).
  • Low-order \(n\) bits represent the Page Offset (\(d\)).

Figure 6.1: Paging Hardware Address Translation Architecture showing Page Table lookup and Offset concatenation.

Step-by-Step Translation Algorithm:

  1. Extract page number \(p\) and offset \(d\) from the logical address.
  2. Use \(p\) as an index into the process's Page Table.
  3. Retrieve corresponding physical frame number \(f\) from the page table entry.
  4. Concatenate frame number \(f\) with original offset \(d\) to produce the physical memory address: \(\mathbf{\text{Physical Address} = (f \times \text{Page Size}) + d}\).

1.2 The Translation Lookaside Buffer (TLB) & Effective Access Time (EAT)

Because page tables reside in main RAM, standard paging requires two memory accesses for every instruction: (1) access RAM to read the page table entry, and (2) access RAM to read the actual instruction/data. This slows memory execution speed by 50%!

Hardware Solution: Translation Lookaside Buffer (TLB)

The TLB is a high-speed associative hardware cache integrated directly onto the CPU silicon. A TLB lookup is performed by associative hardware and is much faster than a main-memory access; its exact latency depends on the processor.

Effective Access Time (EAT) Formula:

Let:

  • \(\alpha\) = TLB Hit Ratio (percentage of times page number is found in the TLB).
  • \(\epsilon\) = TLB Lookup Time (typically \(\approx 1\text{ to } 10\text{ ns}\)).
  • \(t_m\) = Main Memory Access Time (typically \(\approx 100\text{ ns}\)).

When there is a TLB Hit, physical access time is \(\epsilon + t_m\). When there is a TLB Miss, access time is \(\epsilon + 2 t_m\) (TLB search + page table RAM access + payload RAM access). Thus:

$$\mathbf{\text{EAT} = \alpha (\epsilon + t_m) + (1 - \alpha)(\epsilon + 2 t_m) = \epsilon + (2 - \alpha) t_m}$$

1.3 Demand Paging & The 6-Step Page Fault Handling Sequence

In Demand Paging, pages are brought into physical RAM only when demanded during execution (Lazy Swapper). Each page table entry contains a Valid / Invalid Bit:

  • Bit = 1 (Valid): Page is currently loaded in physical RAM.
  • Bit = 0 (Invalid): Page is not in RAM (resides on disk backing store), or address is illegal.

1.4 Page Replacement Algorithms

When a page fault occurs and there are no free frames left in physical RAM, the OS must select a victim frame to page out to disk. This is governed by Page Replacement Algorithms:

Algorithm Eviction Decision Rule Implementation Complexity Optimality / Performance
FIFO (First-In, First-Out) Evicts the page that has resided in RAM for the longest elapsed time (oldest arrival). Trivial: Simple FIFO queue of frames. Poor. Often replaces heavily used initialization variables; suffers from Belady's Anomaly!
Optimal (OPT / MIN) Evicts the page that will not be used for the longest period of time in the future. Impossible in practice: Requires psychic knowledge of future references. Used as optimal benchmark. Provably Optimal: Guaranteed lowest possible page fault count for any fixed frame allocation.
LRU (Least Recently Used) Evicts the page that has not been accessed for the longest period of time in the past. High: Requires hardware timestamps or an active double-linked stack updated on every memory access. Excellent: Approximates Optimal algorithm by utilizing the principle of temporal locality.
Second-Chance (Clock) FIFO with a Reference Bit. If bit = 0, evict. If bit = 1, give second chance: clear bit to 0 and advance pointer. Low: Circular buffer (clock pointer) with a single hardware reference bit per frame. Good approximation of LRU with negligible hardware overhead.

1.5 Belady's Anomaly (Frequent NMIMS Exam Question)

Definition: Belady's Anomaly

Intuitively, giving a process more physical page frames should decrease (or at least keep constant) the number of page faults. Belady's Anomaly is the counter-intuitive phenomenon where increasing the number of page frames allocated to a process results in MORE page faults!

Which algorithms suffer from it? First-In, First-Out (FIFO) suffers from Belady's Anomaly.
Which algorithms are immune? A class of algorithms called Stack Algorithms (such as LRU and Optimal) can mathematically NEVER suffer from Belady's Anomaly, because the set of pages in an \(n\)-frame memory is always a strict subset of the pages in an \((n+1)\)-frame memory.

1.6 Thrashing & The Working-Set Model

If a process does not have enough frames to hold its active working set of pages, it quickly faults. It evicts a page, but immediately needs that evicted page back, faulting again instantly.

Definition: Thrashing

Thrashing occurs when a system spends substantially more time paging (reading/writing to swap disk) than executing useful application instructions. CPU utilization plummets to near zero because all processes are queued waiting for the paging disk!

Prevention via Working-Set Model (Peter Denning):

Based on the principle of Locality of Reference. The operating system defines a working-set parameter \(\Delta\) (a fixed number of recent page references). The Working Set of process \(P_i\) is the set of pages referenced in the most recent \(\Delta\) time units. If total system demand \(D = \sum |WS_i| > \text{Total RAM Frames}\), thrashing will occur. The OS prevents thrashing by suspending (swapping out) one entire process until total demand \(D \le \text{RAM}\).

2. In-Depth Paging & Replacement Numericals

NMIMS 10-Mark Solved Problems
Effective Access Time (EAT)

Problem 6.1: TLB Hit Ratio & Effective Access Time Calculation

Problem Statement: Consider a paging system where the TLB access time is \(20\text{ ns}\) and main memory access time is \(100\text{ ns}\).
(a) Calculate Effective Access Time (EAT) if the TLB hit ratio is \(80\%\).
(b) Calculate EAT if the TLB hit ratio is upgraded to \(98\%\).

FORMULA
$$\text{EAT} = \alpha (\text{TLB} + \text{RAM}) + (1 - \alpha)(\text{TLB} + 2 \times \text{RAM})$$
CALCULATIONS

Part (a): Hit Ratio \(\alpha = 0.80\):

$$\text{EAT}_{80\%} = 0.80(20 + 100) + 0.20(20 + 200) = 0.80(120) + 0.20(220) = 96 + 44 = \mathbf{140\text{ ns}}$$

Part (b): Hit Ratio \(\alpha = 0.98\):

$$\text{EAT}_{98\%} = 0.98(120) + 0.02(220) = 117.6 + 4.4 = \mathbf{122\text{ ns}}$$
CONCLUSION

\(\text{EAT at } 80\% = \mathbf{140\text{ ns}} \quad \longrightarrow \quad \text{EAT at } 98\% = \mathbf{122\text{ ns}}\) (12.9% lower access time (about 14.8% higher throughput).)

Core 10-Mark Problem

Problem 6.2: Complete Page Replacement Trace (FIFO, LRU & Optimal)

Problem Statement (From NMIMS Paper 2 & Paper 4): A system allocates \(4\text{ frames}\) to a process. All frames are initially empty. Consider the page reference string: $$\mathbf{1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5}$$ Compute the number of page faults and page hits for:
(a) First-In, First-Out (FIFO)
(b) Least Recently Used (LRU)
(c) Optimal (OPT)

PART (a) FIFO

FIFO Step-by-Step Trace (4 Frames):

  • Refs 1, 2, 3, 4: Fill frames: \([1, 2, 3, 4]\) \(\to\) 4 Faults
  • Ref 1: Already in frame \(\to\) Hit
  • Ref 2: Already in frame \(\to\) Hit
  • Ref 5: Evict oldest (1). Frames: \([5, 2, 3, 4]\) \(\to\) Fault (5)
  • Ref 1: Evict oldest (2). Frames: \([5, 1, 3, 4]\) \(\to\) Fault (6)
  • Ref 2: Evict oldest (3). Frames: \([5, 1, 2, 4]\) \(\to\) Fault (7)
  • Ref 3: Evict oldest (4). Frames: \([5, 1, 2, 3]\) \(\to\) Fault (8)
  • Ref 4: Evict oldest (5). Frames: \([4, 1, 2, 3]\) \(\to\) Fault (9)
  • Ref 5: Evict oldest (1). Frames: \([4, 5, 2, 3]\) \(\to\) Fault (10)

FIFO Total Faults = 10, Hits = 2.

PART (b) LRU

LRU Step-by-Step Trace (4 Frames):

  • Refs 1, 2, 3, 4: Fill frames: \([1, 2, 3, 4]\) \(\to\) 4 Faults
  • Ref 1: Recent order: 2, 3, 4, 1 \(\to\) Hit
  • Ref 2: Recent order: 3, 4, 1, 2 \(\to\) Hit
  • Ref 5: Evict least recently used (3). Frames: \([1, 2, 5, 4]\) \(\to\) Fault (5)
  • Ref 1: Already in frame. Recent: 4, 2, 5, 1 \(\to\) Hit
  • Ref 2: Already in frame. Recent: 4, 5, 1, 2 \(\to\) Hit
  • Ref 3: Evict least recently used (4). Frames: \([1, 2, 5, 3]\) \(\to\) Fault (6)
  • Ref 4: Evict least recently used (5). Frames: \([1, 2, 4, 3]\) \(\to\) Fault (7)
  • Ref 5: Evict least recently used (1). Frames: \([5, 2, 4, 3]\) \(\to\) Fault (8)

LRU Total Faults = 8, Hits = 4.

PART (c) OPTIMAL

Optimal Step-by-Step Trace (4 Frames):

  • Refs 1, 2, 3, 4: Fill frames: \([1, 2, 3, 4]\) \(\to\) 4 Faults
  • Ref 1: In frame \(\to\) Hit
  • Ref 2: In frame \(\to\) Hit
  • Ref 5: Future lookahead: 1, 2, 3, 4, 5. Page 3 and 4 appear latest. Evict 4. Frames: \([1, 2, 3, 5]\) \(\to\) Fault (5)
  • Ref 1: In frame \(\to\) Hit
  • Ref 2: In frame \(\to\) Hit
  • Ref 3: In frame \(\to\) Hit
  • Ref 4: Future lookahead: 5. Evicts 1, 2, or 3. Evict 1. Frames: \([4, 2, 3, 5]\) \(\to\) Fault (6)
  • Ref 5: In frame \(\to\) Hit

Optimal Total Faults = 6, Hits = 6.

3. Comprehensive Comparative Studies

Frequent Exam Distinctions

Table 6.1: Local vs. Global Page Replacement

Dimension Local Page Replacement Global Page Replacement
Candidate Frame Pool Process selects a replacement frame strictly from its own allocated set of frames. Process can select a victim frame from the entire pool of all system frames (stealing frames from other jobs).
Process Isolation High: One process thrashing does not degrade the execution speed of unrelated jobs. Low: A thrashing process can steal frames from healthy jobs, spreading thrashing system-wide.
Throughput May underutilize RAM if a process needs fewer frames than allocated. Higher overall system throughput in normal non-overcommitted conditions.

4. Production Virtual Memory (x86_64)

Modern CPU Architecture
x86_64 4-Level Paging

48-Bit Virtual Memory in Modern Intel / AMD Processors

Modern 64-bit processors cannot maintain a single flat page table (a \(2^{64}\) entry table would consume billions of gigabytes of RAM!). Instead, x86_64 implements 4-Level Hierarchical Paging:

  • Virtual addresses use 48 active bits: 9 bits for PML4, 9 bits for Page Directory Pointer, 9 bits for Page Directory, 9 bits for Page Table, and 12 bits for physical 4 KB Offset.
  • The hardware CR3 register holds the physical base address of the top-level PML4 table.
  • Non-allocated address ranges require no sub-tables, reducing per-process page table RAM overhead to just a few kilobytes!
