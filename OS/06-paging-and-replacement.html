1. Pages, frames, and a page fault

Paging maps fixed-sized virtual pages to same-sized physical frames. The process issues a page-reference sequence. If the referenced page is not resident, it is a page fault. If frames are full, replacement chooses a victim; count faults consistently, including initial loads.

Reference: 2, 1, 2, 3
3 frames: [2, -, -] → [2,1,-] → hit → [2,1,3]
Misses/faults occur only when requested page is absent.

2. Replacement policies

PolicyVictim ruleKey issue
FIFOOldest loaded pageSimple; may exhibit Belady’s anomaly.
Optimal (OPT)Page whose next use is farthest in future (or never used again)Not implementable online; benchmark lower bound.
LRULeast recently referenced pageUses past behavior as a proxy; ties are impossible under exact reference order.

Simulation: write the frame contents after every reference, mark hit/fault, and track FIFO arrival order or LRU last-use order separately. Never confuse FIFO age with least recent use.

3. Belady’s anomaly and checking

FIFO can incur more faults with more frames; this is Belady’s anomaly. LRU and OPT are stack algorithms and do not have that anomaly. Sanity checks: faults cannot exceed reference count; initial faults occur until frames fill (unless duplicate page hits); count hit/fault separately from replacement; every victim must actually be resident.

The deck’s sample sequence is 1,2,3,2,1,4,3,5,6,4,3,5,3,5,6,7,2,1,5,7 with three frames, to compare OPT, FIFO, LRU.

Recap and self-test

Self-test (answers follow)

Which policy needs future knowledge?

Optimal.

Which policy removes the page loaded earliest?

FIFO.

What history does LRU use?

The most recent past reference time for each resident page.

Can FIFO faults rise when frame count rises?

Yes; Belady’s anomaly.

A referenced page is resident. Fault or hit?

Hit; do not increment the fault count.

4. Demand paging and replacement beyond the basic trio

A valid-invalid page-table bit can mean resident versus not resident (the slides also use valid to mean legal address-space page; distinguish these meanings by the stated scheme). A page fault traps to the OS, which validates the reference, finds/allocates a frame, performs I/O, updates tables and restarts the instruction. A dirty victim must be written back; replacement may require two transfers and increase effective access time.

Second chance/clock: FIFO plus reference bit. If the candidate bit is 0, replace it; if 1, clear it and skip to the next candidate. Global replacement can take frames from any process; local replacement restricts a process to its assigned frames. Global tends to improve overall throughput but can make a process’s behavior vary; local gives more predictable per-process allocation but may leave memory underused.

Frame allocation decides how many frames each process gets; replacement chooses which resident page leaves. These are related but distinct decisions. Reclaiming pages can maintain a free-frame reserve.

5. Source traces worth knowing

The Unit 5 deck gives the reference string 7,0,1,2,0,3,0,4,2,3,0,3,0,3,2,1,2,0,1,7,0,1 and reports FIFO with three frames as 15 faults, OPT as 9, and LRU as 12. It also gives the Belady string 1,2,3,4,1,2,5,1,2,3,4,5. Be prepared to trace every reference, not memorize the totals alone.
