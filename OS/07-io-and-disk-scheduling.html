1.1 I/O Hardware Architecture, Ports & Buses

The computer's I/O architecture bridges high-speed CPU logic with vastly diverse, slower physical peripherals (keyboards, hard disks, GPUs, network cards).

  • Device Controller: A dedicated collection of electronics (chips or circuit boards) that operates a physical device. It maintains a set of hardware registers:
    • Data-In Register: Read by the CPU to receive input bytes.
    • Data-Out Register: Written by the CPU to send output bytes.
    • Status Register: Contains state bits (e.g., BUSY, READY, ERROR).
    • Control Register: Written by the CPU to initiate hardware commands (e.g., read sector, seek track).
  • Controller Interfaces: The CPU communicates with controller registers via Direct I/O Instructions (special machine instructions like in/out) or Memory-Mapped I/O (device registers are mapped directly into the CPU's physical memory address space).

1.2 The Three Fundamental Modes of I/O Execution

Execution Mode Operating Mechanism CPU Utilization & Overhead
1. Programmed I/O (Polling / Busy-Waiting) The CPU issues an I/O command and enters an intensive tight loop repeatedly reading the controller's Status Register until BUSY = 0. Terrible: The CPU is 100% busy doing completely useless polling spinning, starving all other ready processes.
2. Interrupt-Driven I/O The CPU issues an I/O command to the controller and immediately context-switches to execute another ready process. When the device finishes transfer, the hardware controller asserts an interrupt signal line on the CPU bus, triggering an Interrupt Service Routine (ISR). Greatly Improved: CPU never sits idle during physical I/O transfer. However, for massive high-speed data transfers (e.g., gigabit network or disk reads), interrupting the CPU for *every single byte* wastes CPU cycles on interrupt handling.
3. Direct Memory Access (DMA) A dedicated hardware coprocessor—the DMA Controller—transfers an entire block of data directly between the device buffer and main memory without passing through the CPU! The CPU only sets up the transfer (specifying source, destination, and byte count) and receives a single interrupt when the entire multi-megabyte block transfer is complete. Optimal: Frees the CPU entirely during bulk data transfers. CPU cycle stealing occurs only at the memory bus arbitration level.

1.3 I/O Buffering Techniques (Single, Double & Circular)

A Buffer is a designated region of main memory used to hold data in transit between two devices or between an application and an I/O device. Buffering resolves three problems: (1) Coping with device speed mismatches, (2) Adapting between devices that have different data transfer sizes, and (3) Supporting copy semantics for application writes.

Comparative Mathematics of Buffering:

Let \(T\) = Time required to input a block from secondary device into buffer.
Let \(C\) = Computation time required by the CPU to process the block.
Let \(M\) = Time required to move data from OS kernel buffer to user space memory.

  • No Buffering: Execution is strictly sequential: $$\text{Total Time per Block} = T + C$$
  • Single Buffering: The OS assigns a single memory buffer. The I/O device transfers the next block into the buffer while the CPU processes the previous block in user memory: $$\text{Total Time per Block} = \max(T, C) + M$$
  • Double Buffering (Ping-Pong Buffering): The OS assigns two buffers. While the device fills Buffer A, the CPU reads and processes Buffer B. When both finish, their roles are swapped instantaneously: $$\text{Total Time per Block} = \mathbf{\max(T, C)}$$ If \(C \le T\), the CPU is never blocked waiting for I/O; the I/O transfer runs at maximum physical bus speed!

1.4 Physical Magnetic Disk Geometry & Access Times

Traditional magnetic hard disks consist of multiple platters coated with magnetic material spinning at high angular velocities (typically 5,400 to 15,000 RPM).

Figure 7.1: Physical Magnetic Disk Platter, Tracks, Cylinders, and R/W Head Actuator Assembly.

The Three Components of Disk Access Time:

  1. 1. Seek Time (\(T_s\)): The mechanical time required for the actuator arm to physically move the Read/Write head across platters to the target cylinder (track). (This is the dominant bottleneck, typically 3 to 10 milliseconds!).
  2. 2. Rotational Latency (\(T_r\)): The time spent waiting for the target disk sector to rotate under the Read/Write head. $$T_r = \frac{1}{2} \times \frac{60}{\text{RPM}}\text{ s} = \frac{30{,}000}{\text{RPM}}\text{ ms}$$ (For 7,200 RPM drive: \(T_r = \frac{30{,}000}{7200} = 4.17\text{ ms}\)).
  3. 3. Transfer Time (\(T_t\)): The time required to magnetically stream bytes of data off the platter: $$T_t = \frac{\text{Bytes to Transfer}}{\text{Transfer Rate}}$$
$$\mathbf{\text{Total Access Time} = \text{Seek Time } (T_s) + \text{Rotational Latency } (T_r) + \text{Transfer Time } (T_t)}$$

1.5 The Six Disk Scheduling Algorithms

Because physical mechanical head movement is the slowest component of computing, the operating system maintains a request queue of pending disk I/O cylinder requests. Disk Scheduling minimizes total head seek distance.

Algorithm Head Movement & Service Logic Starvation Risk? Trade-offs & Characteristics
1. FCFS Services pending requests strictly in the order they arrive in the I/O queue. No Completely fair, zero algorithmic overhead. Wild, erratic head swings across the disk surface.
2. SSTF (Shortest Seek Time First) Selects the pending request that is closest to the current head position (minimum seek distance). Yes (requests at distant cylinders starve if closer requests keep arriving!) Substantially lowers average seek time compared to FCFS; not optimal.
3. SCAN (Elevator Algorithm) The disk arm moves continuously in one direction (e.g., toward spindle 0), servicing all pending requests along the way, until it reaches the absolute boundary cylinder (0 or Max). There, it reverses direction and sweeps back. No Fair and bounded; however, requests immediately behind the reversing arm wait the longest.
4. C-SCAN (Circular SCAN) Sweeps in one direction servicing requests. When it reaches the boundary, it immediately returns to the opposite boundary without servicing any requests on the return trip! No Provides a vastly more uniform waiting time distribution than standard SCAN.
5. LOOK Variant of SCAN: Arm moves in one direction servicing requests, but only travels as far as the final pending request in that direction! It reverses immediately without traveling to the unneeded physical disk edge (0 or 199). No Eliminates useless wasted arm sweeps to the physical platter boundaries.
6. C-LOOK Variant of C-SCAN: Arm sweeps in one direction up to the last pending request, then jumps directly to the lowest pending request at the other end without touching the physical edges. No Modern default standard for mechanical hard disk drives.

1.6 Blocking, Non-Blocking, and Asynchronous I/O

These terms describe when an application call returns and how completion is reported. They are separate from the lower-level programmed-I/O, interrupt, or DMA transfer mechanism.

ModeCall behaviorCompletion
BlockingThe calling thread waits until the operation completes (or reaches the requested condition).Results are available when the call returns.
Non-blockingThe call returns promptly if it cannot make progress immediately.The caller checks again or waits for readiness, then retries/continues.
AsynchronousThe caller submits work and continues without waiting for its completion.The OS/runtime notifies or signals completion later; the caller then collects the result.

Terminology varies across APIs. In particular, non-blocking I/O commonly reports readiness for a later operation, while asynchronous I/O commonly reports completion of an already submitted operation.

2. In-Depth Disk Scheduling Numericals

NMIMS 10-Mark Solved Calculations
Core 10-Mark Problem

Problem 7.1: Comprehensive Disk Scheduling Comparison (200 Cylinders)

Problem Statement (From NMIMS Paper 1, 2, 3, 5): Suppose that a disk drive has \(200\text{ cylinders}\) numbered from \(0\text{ to } 199\). The disk head is currently positioned at cylinder \(53\). The queue of pending requests in FIFO order is: $$\mathbf{98, 183, 37, 122, 14, 124, 65, 67}$$ Calculate the Total Head Movement (in cylinders) and illustrate the head seek trajectory for:
(a) FCFS
(b) SSTF
(c) SCAN (Assume arm moves toward cylinder 0 / decreasing)
(d) LOOK (Assume arm moves toward cylinder 0 / decreasing)
(e) C-SCAN (Assume arm moves toward cylinder 199 / increasing)

PART (a) FCFS

Order of Service: \(53 \to 98 \to 183 \to 37 \to 122 \to 14 \to 124 \to 65 \to 67\)

Calculations:

$$|98 - 53| + |183 - 98| + |37 - 183| + |122 - 37| + |14 - 122| + |124 - 14| + |65 - 124| + |67 - 65|$$ $$= 45 + 85 + 146 + 85 + 108 + 110 + 59 + 2 = \mathbf{640\text{ cylinders}}$$
PART (b) SSTF

Start at \(53\). Closest is 65 (\(\Delta 12\)), then 67 (\(\Delta 2\)), then 37 (\(\Delta 30\)), then 14 (\(\Delta 23\)), then 98 (\(\Delta 84\)), then 122 (\(\Delta 24\)), then 124 (\(\Delta 2\)), then 183 (\(\Delta 59\)).

Order of Service: \(53 \to 65 \to 67 \to 37 \to 14 \to 98 \to 122 \to 124 \to 183\)

Calculations:

$$(67 - 53) + (67 - 14) + (183 - 14) = 14 + 53 + 169 = \mathbf{236\text{ cylinders}}$$
PART (c) SCAN

Start at \(53\), moving toward 0. Services pending requests below 53: 37, 14, then touches boundary 0, then reverses toward 199: 65, 67, 98, 122, 124, 183.

Order of Service: \(53 \to 37 \to 14 \to \mathbf{0} \to 65 \to 67 \to 98 \to 122 \to 124 \to 183\)

Calculations:

$$\text{Total Head Movement} = (53 - 0) + (183 - 0) = 53 + 183 = \mathbf{236\text{ cylinders}}$$
PART (d) LOOK

Start at \(53\), moving toward 0. Services 37, 14. Lowest request is 14; reverses immediately without going to 0!

Order of Service: \(53 \to 37 \to 14 \to 65 \to 67 \to 98 \to 122 \to 124 \to 183\)

Calculations:

$$\text{Total Head Movement} = (53 - 14) + (183 - 14) = 39 + 169 = \mathbf{208\text{ cylinders}}$$
PART (e) C-SCAN

Start at \(53\), moving toward 199. Services: 65, 67, 98, 122, 124, 183 \(\to\) touches 199 \(\to\) jumps to 0 \(\to\) services: 14, 37.

Order of Service: \(53 \to 65 \to 67 \to 98 \to 122 \to 124 \to 183 \to \mathbf{199} \to \mathbf{0} \to 14 \to 37\)

Calculations:

$$\text{Total Head Movement} = (199 - 53) + (199 - 0) + (37 - 0) = 146 + 199 + 37 = \mathbf{382\text{ cylinders}}$$

SSTF236 cylindersHighly efficient (starvation risk)

4. Enterprise Storage Architecture (RAID Levels)

Data Redundancy & Performance
RAID Architecture

RAID: Redundant Array of Independent Disks

  • RAID 0 (Striping): Blocks striped across \(N\) disks. Maximum I/O throughput. Zero fault tolerance (failure of 1 disk loses all data).
  • RAID 1 (Mirroring): Complete data duplication across pairs of drives. 100% capacity overhead; instant recovery upon disk crash.
  • RAID 5 (Block-Level Striping with Distributed Parity): Data blocks and XOR parity blocks distributed across \(\ge 3\) disks. Tolerates failure of any single disk with only \(1/N\) capacity overhead!
