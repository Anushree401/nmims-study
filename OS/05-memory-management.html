1. Address spaces and protection

Programs are stored on backing storage and must be loaded to run. The CPU generates logical (virtual) addresses; memory uses physical addresses. The MMU maps between them. With relocation register R, a logical address L maps to physical R+L, provided it lies inside the process limit. Base/limit protection checks each user-mode reference; loading these privileged registers is restricted.

Address binding may occur at compile time (known location; absolute code), load time (relocatable code), or execution time (dynamic mapping; process may move). Logical and physical addresses can be identical in compile/load binding; with execution-time binding they differ.

2. Allocation and fragmentation

Contiguous allocation gives a process one continuous region; variable partitions can leave external fragmentation (free holes between allocated blocks). Internal fragmentation is wasted space inside an allocated block. Compaction can combine holes if relocation is supported. First-fit chooses the first adequate hole, best-fit the smallest adequate hole, worst-fit the largest. These policies affect search and fragmentation; no single rule eliminates all waste.

Paging divides logical memory into fixed-size pages and physical memory into frames of the same size. A page table maps page number to frame number. For page size S, logical address A gives page number p=⌊A/S⌋ and offset d=A mod S; physical address=frame(p)×S+d. Paging removes external fragmentation but can leave internal waste in the last page and costs page-table storage/translation.

3. Virtual memory concepts

Virtual memory allows a process’s address space to exceed currently resident memory. Demand paging loads a page when referenced; a missing page causes a page fault, OS brings it in, updates the mapping, and restarts the instruction. If no free frame exists, a replacement algorithm selects a victim. Too many faults can cause thrashing: the system spends time paging rather than executing.

Recap and self-test

Self-test (answers follow)

How does relocation translate an address?

Physical=relocation/base value + logical address, subject to bounds protection.

Paging uses which same-sized units?

Logical pages and physical frames.

What problem does paging remove, and what waste can remain?

It removes external fragmentation; internal fragmentation, especially in the final page, can remain.

How are page and offset computed for page size S?

p=floor(A/S), d=A mod S.

What is thrashing?

Excessive paging/page faults that consume time and impair useful execution.

4. Variable partitions and fit policies

Variable-sized partitions are carved from free holes. First-fit takes the first sufficiently large hole; best-fit takes the smallest adequate hole; worst-fit takes the largest. After allocation, subtract the requested size from that hole; merge adjacent free holes when a process exits. External fragmentation means total free space is sufficient but split across noncontiguous holes. Internal fragmentation is unused space inside an allocated partition. Compaction gathers holes and requires dynamic relocation; I/O to a process being moved must be handled safely.

Slide example (K): holes 100, 500, 200, 300, 600; requests 212, 417, 112, 426, in that order. First-fit leaves after each allocation: (100,288,200,300,600) → (100,288,200,300,183) → (100,176,200,300,183); 426 cannot fit. Best-fit: 212 uses 300 (88 left); 417 uses 500 (83 left); 112 uses 200 (88 left); 426 uses 600 (174 left). Worst-fit: 212 uses 600 (388 left); 417 uses 500 (83 left); 112 uses remaining 388 (276 left); 426 cannot fit. Best-fit places all four requests, but “most efficient” depends on the chosen measure and future requests; do not claim a universal winner.

5. Segmentation

Segmentation reflects the programmer’s logical view: a program consists of variable-sized units such as procedures, functions, stack, arrays, and data. A logical address is <segment s, offset d>. The segment-table entry supplies base and limit. Check s<STLR and d<limit; then physical address=base[s]+d. Out-of-range segment or offset traps. Unlike paging, segment sizes vary and external fragmentation can occur.

6. Paging hardware, TLB, protection, and EAT

Page tables map page numbers to frame numbers. PTBR points to the table; PTLR gives its length. Without a TLB, translation may require a page-table memory access plus the actual memory access. A TLB is a small associative cache of translations; ASIDs tag entries by process, otherwise context switches may flush it. Valid/invalid bits distinguish legal address-space pages; protection bits can encode read/write/execute rights.

If memory access time is m and TLB hit ratio is h, with no TLB lookup cost and one memory access on hit/two on miss: EAT=h·m+(1−h)·2m. For m=10 ns,h=.80: EAT=12 ns. At h=.99: EAT=10.1 ns. If lookup time is supplied, include it according to hit/miss path.

Large page tables motivate hierarchical, hashed, or inverted page-table structures. The slides name these approaches but do not detail their algorithms.

7. Swapping and virtual memory

Swapping temporarily moves a process image to backing store; transfer time depends on data size and storage rate. Example: 100 MB at 50 MB/s takes 2 s per transfer; swapping one process out and another of equal size in takes about 4 s, excluding overhead. Pending I/O complicates movement; double buffering through kernel memory adds copying. Virtual memory separates logical from physical size and loads only needed pages (demand paging), allowing sparse address spaces, shared pages, and more concurrent programs.

Demand-paging fault handling: validate reference; abort if illegal; otherwise find free frame or select victim, write dirty victim if needed, load page, update tables/valid bit, restart instruction. Pure demand paging begins with no pages resident. If a process lacks enough frames, repeated faults can cause thrashing and low CPU utilization.
