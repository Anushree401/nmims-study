1.1 Address Binding Lifecycles & Hardware Protection

Programs are stored on secondary disk storage as binary executable files. To run, they must be brought into main physical RAM and placed inside an active process context.

The Three Phases of Address Binding:

Address binding is the mapping of program instructions and data to physical memory addresses. It occurs at three distinct stages:

  1. Compile Time: If it is known at compile time where the process will reside in physical RAM, absolute machine code is generated (e.g., instructions directly reference physical address 0x00400000).
    Severe Limitation: If the starting memory location changes later, the entire program must be completely recompiled! (Used historically in MS-DOS .COM files).
  2. Load Time: If memory location is not known at compile time, the compiler generates relocatable code. Final binding of memory addresses is delayed until the loader places the program into RAM.
    Limitation: If the process is swapped out to disk and reloaded later into a different RAM partition, all internal pointers break!
  3. Execution Time (Run Time - Modern Standard): If a process can be moved during its execution from one memory segment to another (e.g., via swapping), binding must be delayed until run time.
    Hardware Requirement: Requires special hardware support: the Memory Management Unit (MMU) with dynamic relocation registers.

Hardware Address Protection: Base and Limit Registers

To ensure a user process cannot corrupt kernel memory or read data from another process, the CPU hardware implements two dedicated registers:

  • Base Register: Holds the smallest legal physical memory address allocated to the process (e.g., 300040).
  • Limit Register: Specifies the total size/range of the logical address space allocated to the process (e.g., 120900).

1.2 Logical vs. Physical Address Spaces & Dynamic Relocation

Logical vs. Physical Addresses (The Essential Distinction):

  • Logical Address (Virtual Address): An address generated by the CPU during instruction execution. To the program, it appears as though it owns memory starting from address 0x00000000.
  • Physical Address: The actual physical hardware memory location loaded onto the memory address bus of the RAM chips.

The hardware device that performs run-time mapping from logical to physical addresses is the Memory Management Unit (MMU).

The Relocation Register:

In the simplest dynamic relocation scheme, the Base register is called a Relocation Register. The value in the relocation register is added to every address generated by a user process at the hardware bus level:

$$\mathbf{\text{Physical Address} = \text{Logical Address} + \text{Relocation Register Value}}$$

Example: If the Relocation Register holds 14000, a CPU request for logical address 346 maps directly to physical RAM address \(14000 + 346 = \mathbf{14346}\). The user program never knows or cares about physical address 14346!

1.3 Swapping & The Backing Store

A process must reside in physical RAM to execute. However, when total memory demanded by active jobs exceeds physical RAM capacity, the operating system invokes Swapping:

  • A process can be temporarily swapped out of memory to a backing store (a high-speed secondary disk partition / swap space), and later brought back (swapped in) to continue execution.
  • Context Switch Overhead in Swapping: Swapping incurs massive time overhead because disk transfer speeds are orders of magnitude slower than RAM bus transfers.
    Calculation: Swapping out a 100 MB process to a disk with transfer rate of 50 MB/s takes \(100\text{ MB} / 50\text{ MB/s} = 2.0\text{ seconds}\)! This dwarfs normal CPU microsecond switching.

1.4 Contiguous Memory Allocation & Dynamic Partitioning Strategies

In contiguous memory allocation, each process is loaded into a single contiguous block of physical memory addresses. As processes enter and exit RAM, variable-sized holes (free memory blocks) are created throughout physical memory.

The Three Dynamic Storage Allocation Strategies:

Allocation Strategy Algorithmic Selection Logic Computational Search Overhead Fragmentation Characteristics
First-Fit Allocate the very first free hole that is large enough to satisfy the request. Search can start at beginning or where previous search ended. Fastest. Stops searching the moment a qualifying hole is found. Generates small unusable slivers of external fragmentation at the beginning of memory.
Best-Fit Allocate the smallest hole that is large enough. Must search the entire list unless ordered by size. Slower. Must inspect every free block in memory. Produces the smallest leftover leftover holes, which are often too tiny to ever satisfy future requests.
Worst-Fit Allocate the largest available hole in memory. Must search the entire list unless ordered by size. Slower. Must inspect every free block to find the maximum. Leaves behind the largest remaining residual hole, which is more likely to be useful for subsequent processes.

Empirical Research Findings (Stallings & Silberschatz):

Simulations prove that both First-Fit and Best-Fit are strictly superior to Worst-Fit in terms of execution speed and memory storage utilization. First-Fit is generally the fastest and most memory-efficient in practice.

1.5 Internal vs. External Fragmentation (NMIMS Exam Classic)

Fragmentation is the severe degradation of memory utilization where free storage is wasted.

Comparison Dimension Internal Fragmentation External Fragmentation
Fundamental Definition Wasted storage space residing inside an allocated memory partition because the assigned block is slightly larger than the requested process payload. Wasted storage space residing outside allocated partitions (between processes). Total free memory is sufficient, but broken into non-contiguous fragments.
Occurs Under Which Scheme? Occurs in Fixed-Partition Multiprogramming and Paging (within the final frame). Occurs in Variable-Partition Contiguous Allocation and Segmentation.
Root Cause System allocates memory in discrete, fixed-size chunks (e.g., 4 KB pages or fixed 100 KB partitions). Continuous allocation and deallocation of variable-sized process blocks over time.
The 50-Percent Rule Not governed by the 50% rule. Statistical analysis proves: for First-Fit, given \(N\) allocated blocks, another \(0.5 N\) blocks are lost to external fragmentation (one third of memory wasted!).
Remediation Strategy Use smaller page sizes (e.g., 4 KB instead of 64 KB). Eliminated by Compaction (shuffling RAM contents) or by adopting Non-Contiguous Paging!

1.6 Segmentation Architecture & Address Translation

Users do not view memory as a linear array of bytes; they view memory as a collection of variable-length logical units: a Main Routine, Subroutines, Symbol Table, Stack, and Arrays. Segmentation is a memory management scheme that directly supports this programmer's view of memory.

Logical Address Structure in Segmentation:

A logical address is a 2-tuple: \(\mathbf{\langle \text{Segment Number } s, \text{ Offset } d \rangle}\).

The Segment Table:

Maps two-dimensional user logical addresses into one-dimensional physical memory. Each entry in the segment table contains:

  • Base: Starting physical address where the segment resides in RAM.
  • Limit: The exact length of the segment.

Figure 5.2: Segmentation Hardware Address Translation showing Limit comparison and Base addition.

Hardware Translation Rule in Segmentation:

  1. Segment number \(s\) indexes into the Segment Table.
  2. Compare offset \(d\) against the segment Limit:
    If \(d \ge \text{Limit} \implies\) TRAP: Addressing Error (Segmentation Fault)!
  3. If \(d < \text{Limit} \implies\) Compute physical address: $$\mathbf{\text{Physical Address} = \text{Base} + d}$$

1.7 Memory Management Requirements and Fixed vs. Variable Partitions

Classical memory management must support relocation (processes need not load at one fixed physical address), protection (one process cannot access another's memory without authorization), sharing (controlled sharing of code/data), and a useful separation between logical program organization and physical memory organization.

Partition schemeAllocation and fragmentationTrade-off
Fixed partitioningRAM is divided into preset partitions; one process occupies a partition. Unused space inside an assigned partition is internal fragmentation.Simple, but partition count and sizes constrain the number and size of resident processes.
Variable (dynamic) partitioningPartitions are created to fit incoming processes. Free holes can form between allocations, causing external fragmentation.More flexible fit, but may need compaction and placement policies such as First/Best/Worst Fit.

2. In-Depth Partitioning Numericals (Step-by-Step)

NMIMS 10-Mark Allocation Problems
Core 10-Mark Problem

Problem 5.1: Process-to-Partition Allocation: First-Fit, Best-Fit & Worst-Fit

Problem Statement (From NMIMS Paper 5 & Paper 2): Consider five memory partitions of sizes: $$100\text{ KB}, \quad 500\text{ KB}, \quad 200\text{ KB}, \quad 300\text{ KB}, \quad 600\text{ KB}$$ (in contiguous order). Consider processes arriving in sequence with memory requirements: $$P_1: 212\text{ KB}, \quad P_2: 417\text{ KB}, \quad P_3: 112\text{ KB}, \quad P_4: 426\text{ KB}$$ Show the final process-to-partition allocation and remaining holes under:
(a) First-Fit
(b) Best-Fit
(c) Worst-Fit
(d) State which algorithm makes the most efficient use of memory.

PART (a) FIRST-FIT

Partitions: \([100\text{ KB}, 500\text{ KB}, 200\text{ KB}, 300\text{ KB}, 600\text{ KB}]\)

  • \(P_1 (212\text{ KB})\): First hole large enough is 500 KB.
    \(\to P_1\) allocated to 500 KB partition (Remaining: \(500 - 212 = 288\text{ KB}\)).
  • \(P_2 (417\text{ KB})\): First hole large enough is 600 KB.
    \(\to P_2\) allocated to 600 KB partition (Remaining: \(600 - 417 = 183\text{ KB}\)).
  • \(P_3 (112\text{ KB})\): First hole large enough is 200 KB.
    \(\to P_3\) allocated to 200 KB partition (Remaining: \(200 - 112 = 88\text{ KB}\)).
  • \(P_4 (426\text{ KB})\): Needs 426 KB. Holes available: 100 KB, 288 KB, 88 KB, 300 KB, 183 KB. None \(\ge 426\) KB!
    \(\to \mathbf{P_4 \text{ must WAIT (Cannot be allocated!)}}\)
PART (b) BEST-FIT

Partitions: \([100\text{ KB}, 500\text{ KB}, 200\text{ KB}, 300\text{ KB}, 600\text{ KB}]\)

  • \(P_1 (212\text{ KB})\): Qualifying holes: 500, 300, 600. Smallest is 300 KB.
    \(\to P_1\) allocated to 300 KB partition (Remaining: \(300 - 212 = 88\text{ KB}\)).
  • \(P_2 (417\text{ KB})\): Qualifying holes: 500, 600. Smallest is 500 KB.
    \(\to P_2\) allocated to 500 KB partition (Remaining: \(500 - 417 = 83\text{ KB}\)).
  • \(P_3 (112\text{ KB})\): Qualifying holes: 200, 600. Smallest is 200 KB.
    \(\to P_3\) allocated to 200 KB partition (Remaining: \(200 - 112 = 88\text{ KB}\)).
  • \(P_4 (426\text{ KB})\): Qualifying hole: 600 KB.
    \(\to P_4\) allocated to 600 KB partition (Remaining: \(600 - 426 = 174\text{ KB}\)).

Result: ALL FOUR PROCESSES ALLOCATED SUCCESSFULLY!

PART (c) WORST-FIT
  • \(P_1 (212\text{ KB})\): Largest hole is 600 KB.
    \(\to P_1\) allocated to 600 KB partition (Remaining: \(600 - 212 = 388\text{ KB}\)).
  • \(P_2 (417\text{ KB})\): Largest hole is 500 KB.
    \(\to P_2\) allocated to 500 KB partition (Remaining: \(500 - 417 = 83\text{ KB}\)).
  • \(P_3 (112\text{ KB})\): Largest hole is 388 KB (leftover of 600 KB).
    \(\to P_3\) allocated to 388 KB partition (Remaining: \(388 - 112 = 276\text{ KB}\)).
  • \(P_4 (426\text{ KB})\): Needs 426 KB. Holes available: 100, 83, 200, 300, 276. Largest is 300 KB.
    \(\to \mathbf{P_4 \text{ must WAIT (Cannot be allocated!)}}\)
CONCLUSION

Best-Fit is the MOST EFFICIENT in this scenario, as it is the ONLY policy capable of allocating all four processes simultaneously without blocking \(P_4\).

4. Real-World Memory Allocators

Kernel Implementation
Linux Slab Allocator

The Linux Buddy System & Slab Allocator

To avoid severe external fragmentation in kernel memory, Linux uses a two-tier allocator:

  • Buddy System: Allocates physical memory in power-of-two page frames (\(4\text{ KB}, 8\text{ KB}, 16\text{ KB}, \dots\)). When a block is released, it is merged with its adjacent "buddy" block into a larger power-of-two block in \(O(1)\) time.
  • Slab Allocator: Eliminates internal fragmentation caused by the Buddy System for small kernel data structures (such as PCBs, semaphores, and file inodes). It pre-allocates contiguous caches of identical small objects.
