1.1 The File Concept, Operations & Metadata Attributes

Computers must store data persistently on secondary non-volatile storage. The operating system abstracts physical storage blocks into a uniform logical storage unit: the File.

Formal Definition of a File

A File is a named collection of related information recorded on secondary storage. From a user's perspective, a file is the smallest allotment of logical secondary storage; data cannot be written to disk unless it is within a named file.

Core File Attributes (Stored in the File Directory / Inode):

  • Name: The human-readable symbolic string identifier (e.g., report.pdf).
  • Identifier: A unique non-human tag (usually an integer like an inode number) that uniquely identifies the file within the filesystem.
  • Type: Required for systems that support different file formats (e.g., executable, text, directory).
  • Location: A pointer to a device and to the physical disk block addresses where file content is stored.
  • Size: Current file size in bytes, words, or disk sectors.
  • Protection: Access-control information determining who can read, write, or execute the file.
  • Timestamps: Time of creation, last modification, and last access (used for caching and backups).

1.2 File Access Methods: Sequential vs. Direct Access

Dimension Sequential Access Method Direct Access (Relative Access) Method
Reading Mechanism Information is processed strictly in chronological order, one record after another. An internal read pointer advances automatically: read_next(). A file is made up of fixed-length logical records. Programs can read or write records in any arbitrary order immediately: read(record_number).
Underlying Storage Analogy Magnetic Tape reel (must wind through preceding miles of tape to reach record 500). Magnetic Disk / SSD (read/write head seeks directly to target cylinder and sector).
Primary Operations read_next(), write_next(), reset() (rewind to beginning). read(n), write(n), seek(n).
Ideal Applications Compilers compiling source code files, audio/video streaming media, sequential log files. Relational Database Management Systems (RDBMS), airline reservation search queries.

1.3 Directory Structures & Topological Evolution

A directory is an internal filesystem data structure that translates human file names into their corresponding directory entries and physical block addresses.

1. Single-Level Directory:

All files reside in a single directory shared by all users.
Fatal Flaws: Severe Name Collision (no two files can have the same name, even if owned by different users!) and total lack of logical grouping.

2. Two-Level Directory:

Creates an isolated Master File Directory (MFD) containing pointers to individual User File Directories (UFDs). Solves name collisions across different users; however, individual users cannot group related files into subdirectories.

3. Tree-Structured Directory (Modern Standard):

Generalizes directories into a tree of arbitrary depth. A directory can contain files and other subdirectories.
Path Names: Every file has a unique Absolute Path Name (starting from root /) and a Relative Path Name (starting from the Current Working Directory - CWD).

4. Acyclic-Graph Directories (Sharing & Aliases):

Allows directories to share subdirectories and files. The same physical file can exist under multiple directory paths (via Hard Links and Soft / Symbolic Links).
Hazard: Dangling pointers if an aliased file is deleted; requires a Reference Count in the file's inode.

1.4 Physical Storage Allocation Methods

The allocation method defines how physical disk blocks are assigned to files:

Allocation Method Physical Disk Block Layout Major Advantages Severe Disadvantages
1. Contiguous Allocation Each file occupies a set of contiguously adjacent disk blocks (e.g., blocks 100, 101, 102). Directory entry stores: \(\langle \text{Start Block}, \text{Length} \rangle\). Maximum Read Speed! Head seeks once to start block; subsequent sectors stream without seek delay. Supports direct access trivial math. Severe External Fragmentation: Wastes disk space; impossible to know final file size in advance when creating files (file expansion requires relocation).
2. Linked Allocation Each file is a linked list of discrete disk blocks scattered anywhere on the disk platter. Each block contains a pointer to the next block. Zero External Fragmentation: Any free block on disk can be allocated instantly. Files grow dynamically without bounds. No Direct Access: To read block \(N\), must follow \(N-1\) disk seek pointers sequentially! Wasted storage (4 to 8 bytes per block used for pointers).
3. File Allocation Table (FAT) Variation of linked allocation: pointers are pulled out of disk blocks and stored in a single table (the FAT) cached in RAM. Faster direct access traversal since pointer hops occur in RAM rather than mechanical disk seeks. Entire FAT table must reside permanently in RAM; large disks require massive tables.
4. Indexed Allocation (UNIX Inodes) Brings all pointers together into a dedicated Index Block for each file. The \(i\)-th entry in the index block points to the \(i\)-th physical block of the file. Supports true Direct Access without external fragmentation. Files can grow dynamically. Index block space overhead: tiny 10-byte files waste an entire 4 KB index block!

1.5 Free Space Management (Bitmaps & Linked Lists)

To allocate disk blocks quickly, the OS maintains a free-space list tracking unallocated sectors:

  • Bit Vector (Bitmap): Each block is represented by a single bit.
    • Bit = 0: Block is allocated.
    • Bit = 1: Block is free.
    Advantage: Exceptionally fast to search for the first free block on modern CPUs using hardware bit-scan instructions (e.g., bsfl on x86). Simple to find contiguous runs of free blocks.
    Overhead: Assuming binary units, a 1 TiB disk with 4 KiB blocks has \(2^{28}\) blocks. The bitmap uses one bit per block, so it requires \(2^{28} \text{ bits} / 8 = 2^{25} \text{ bytes} = 32\text{ MiB}\) of RAM.
  • Linked Free List: Pointers to free blocks are linked together across the free disk blocks themselves. Takes zero RAM overhead; however, traversing the free list requires mechanical disk reads.

1.6 Access Matrix: A General Model of File Protection

An access matrix models protection with subjects (users/processes) as rows, objects (files/devices) as columns, and each cell listing permitted rights such as read, write, or execute. A file-system Access Control List (ACL) is a column-oriented implementation: it records which subjects may perform which operations on one object. Capability lists are a row-oriented view of the same permissions.

Grant only the rights required for a task, and distinguish permission to read a file from permission to modify or execute it.

2. In-Depth File Storage Numericals

Capacity & Index Structure Mathematics
UNIX Multi-Level Inode Problem

Problem 8.1: Maximum File Size in Multi-Level Inode Systems

Problem Statement: Consider a UNIX-style file system where disk blocks are \(4\text{ KiB}\) in size and block addresses/pointers require \(4\text{ bytes}\). An inode contains:

  • \(12\text{ Direct Block Pointers}\)
  • \(1\text{ Singly Indirect Pointer}\)
  • \(1\text{ Doubly Indirect Pointer}\)
  • \(1\text{ Triply Indirect Pointer}\)
Calculate the theoretical Maximum File Size supported by this filesystem.

POINTER CAPACITY

Each index block is \(4\text{ KiB} = 4096\text{ bytes}\). Each pointer is \(4\text{ bytes}\).
Number of pointers per index block (\(K\)):

$$K = \frac{4096\text{ bytes}}{4\text{ bytes}} = 1024\text{ pointers per block} = 2^{10}$$
LEVEL BREAKDOWN
  • 1. Direct Blocks: $$12 \times 4\text{ KiB} = \mathbf{48\text{ KiB}}$$
  • 2. Singly Indirect: Points to 1 index block holding 1024 direct pointers: $$1024 \times 4\text{ KiB} = 4096\text{ KB} = \mathbf{4\text{ MiB}}$$
  • 3. Doubly Indirect: Points to 1 index block holding 1024 singly indirect blocks: $$1024 \times 1024 \times 4\text{ KiB} = 1,048,576 \times 4\text{ KiB} = \mathbf{4\text{ GiB}}$$
  • 4. Triply Indirect: Points to 1 index block holding 1024 doubly indirect blocks: $$1024^3 \times 4\text{ KiB} = 2^{30} \times 4\text{ KiB} = \mathbf{4\text{ TiB}}$$
MAX FILE SIZE
$$\text{Max Size} = 48\text{ KiB} + 4\text{ MiB} + 4\text{ GiB} + 4\text{ TiB} \approx \mathbf{4.00391\text{ TiB}}$$

\(\text{Theoretical Maximum File Size (using binary units)} \approx \mathbf{4.00391\text{ TiB}}\)

Frequent Exam Distinctions

Table 8.1: Master Comparison of File Allocation Methods

Feature Contiguous Allocation Linked Allocation Indexed Allocation
Sequential Access Speed Blindingly fast (zero seek delay between sectors). Slow (requires seeks across platters). Fast (index block cached in RAM).
Direct Access Speed Instant: Address = Start + Offset. Terrible: Must traverse \(N-1\) pointers sequentially. Fast: Index lookup in single hop.

4. Production File Systems (Linux ext4)

Enterprise Storage
Linux ext4 Architecture

Extents & Journaling in Linux ext4

  • Extents Replacement: Traditional UNIX inodes used multi-level indirect block pointers. For massive multi-gigabyte files, traversing indirect tables wasted CPU cycles. Modern ext4 replaces block pointers with Extents: a descriptor storing \(\langle \text{Logical Start}, \text{Length}, \text{Physical Start} \rangle\). A single extent can map up to 128 MB of contiguous blocks in one entry!
  • Journaling (Crash Resilience): Writes filesystem metadata transactions to a circular on-disk journal *before* updating main disk structures, ensuring zero corruption during unexpected power outages.
