1. Deadlock and necessary conditions

A deadlock is a set of processes where each waits for a resource held by another, so none can progress. All four Coffman conditions must hold simultaneously: mutual exclusion, hold-and-wait, no preemption, and circular wait. Breaking any one prevents deadlock.

P1 holds R1 → waits for R2
P2 holds R2 → waits for R1
cycle: P1 → R2 → P2 → R1 → P1

2. Handling strategies

Prevention structurally denies a condition: make resources shareable where possible; request all resources at once or release before requesting more; preempt where safe; impose a total resource order. Each can lower utilization or cause inconvenience. Avoidance grants a request only if the resulting state remains safe. Detection and recovery allow allocation, periodically detect deadlock, then terminate processes or preempt resources. Ignore (ostrich approach) is a pragmatic choice when risk/cost is low, but it does not solve the deadlock.

3. Safe state and Banker’s method

Safe means there exists an ordering in which every process can obtain its remaining Need from currently Available plus resources released by earlier completed processes. Unsafe does not mean deadlocked; it means no safe completion order is currently demonstrated.

Compute Need = Max − Allocation elementwise. To test safety, set Work=Available and Finish=false. Find an unfinished process with Need≤Work for every resource; assume it finishes and set Work=Work+Allocation. Repeat. If all finish, the sequence is safe. For a request, first require Request≤Need and Request≤Available; tentatively subtract from Available, add to Allocation, subtract from Need; run safety test. Commit only if safe.

Example: Available=(3,3,2), process P0 Need=(7,4,3), P1 Need=(1,2,2). P1 can finish first because its Need fits; Work becomes Available+Allocation(P1). Continue similarly. Compare vectors componentwise, not by sum.

4. Resource-allocation graphs, detection, recovery

In a RAG, process nodes and resource-type nodes are different; request edge P→R means waiting, assignment edge R→P means allocated. With one instance per resource, a cycle is sufficient for deadlock. With multiple instances, a cycle is necessary but not sufficient. Detection uses a Work/Finish-style procedure over current Allocation and outstanding requests. Recovery choices include killing all involved, killing one at a time and retesting, or resource preemption; preemption can cause starvation unless victim choice/rollback is managed.

Common traps and self-test

Self-test (answers follow)

Can an unsafe state already be deadlocked?

Yes, but unsafe only means a guaranteed safe sequence is not available; it is not proof of deadlock.

For one-instance resources, what does a RAG cycle imply?

Deadlock.

For multiple instances, is a cycle sufficient?

No. It is necessary but not sufficient.

In Banker’s algorithm, what relation defines Need?

Need=Max−Allocation.

What is the acceptance rule for a tentative request?

Request≤Need, Request≤Available, and the resulting state must pass the safety test.
