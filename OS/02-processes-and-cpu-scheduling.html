1. Program versus process

A program is passive code; a process is an executing instance with code, data, stack, heap, CPU state, and OS-managed resources. The process control block (PCB) records identity/state, scheduling and CPU context, memory-management data, I/O status, open files, accounting, privileges, and IPC/resource information. A context switch saves one process state and restores another.

2. Lifecycle and threads

In the five-state model: New → Ready → Running → Exit. Running may go to Blocked while awaiting an event/I/O, then return to Ready when the event occurs; a timeout may return Running to Ready. Suspended-ready and suspended-blocked states represent swapped-out work. A thread is a schedulable execution path within a process. Threads share process resources/address space but maintain their own registers, stack, and execution state.

User-level threads are managed by a user-space library; kernel-level threads are visible and scheduled by the OS kernel. Thread creation/switching can be cheaper than process creation/switching, and shared-memory communication is convenient, but synchronization is required.

3. Scheduling levels and decisions

Long-term admission controls how many jobs enter the system; medium-term suspension/swapping adjusts the resident set; short-term selection chooses the next ready process. Preemption lets the OS take the CPU away; nonpreemptive scheduling waits for release/block/exit. Scheduling decisions occur at state transitions; preemption in kernel-critical operations requires care.

Common criteria: CPU utilization and throughput should be high; turnaround, waiting, and response times should be low; fairness and predictability matter. Response time is first service minus arrival; turnaround is completion minus arrival; waiting sums time in ready queue. For a single CPU burst, turnaround = waiting + burst if there is no other overhead.

4. Algorithms: choose by what is known

AlgorithmRuleTrade-off/trap
FCFSArrival order; nonpreemptiveSimple, but convoy effect: short jobs wait behind a long job.
SJFShortest next CPU burst; nonpreemptiveMinimizes average waiting when burst lengths are known; future length is hard to know; long jobs may starve.
SRTFPreemptive shortest remaining timeNew arrival can preempt; recalculate remaining time at every arrival/completion.
PriorityHighest priority selected; may be preemptive or notState whether smaller or larger number means higher priority. Aging can mitigate starvation.
Round RobinPreempt after quantum q; append unfinished job to ready tailSmall q improves response but increases switching overhead; very large q approaches FCFS.
Multilevel queueFixed class/queue assignmentQueues may use different policies; fixed assignment limits movement.
Multilevel feedback queueJobs can move between priority queuesFlexible; behavior depends on queue rules and quantum.

5. Worked micro-example and traps

For P1 (arrival 0, burst 5) and P2 (arrival 1, burst 2): FCFS runs P1 0–5, then P2 5–7. P1 turnaround=5, wait=0; P2 turnaround=6, wait=4. Under SRTF, P1 runs 0–1, P2 preempts and runs 1–3, then P1 3–7. P1 turnaround=7, wait=2; P2 turnaround=2, wait=0. This illustrates why a Gantt chart is safer than intuition.

Always handle arrival times, ties, preemption, and context-switch cost as specified. Do not count a blocked interval as ready waiting. Response time is not turnaround time.

Recap and self-test

Self-test (answers follow)

What does a PCB preserve during a context switch?

Process identity/state plus CPU context and resource/scheduling/accounting information needed to resume it.

When does a blocked process become ready?

When the event/I/O it awaited occurs; it does not go straight to running.

For RR, what happens at quantum expiry?

If unfinished, the process is preempted and placed at the ready-queue tail.

A process arrives at t=3 and first runs at t=8. Its response time?

8−3=5 time units.

What is one standard response to priority starvation?

Aging: gradually raise waiting jobs’ priority.

What to know for the exam

Be ready to define the central terms, compare mechanisms using their assumptions and trade-offs, trace a process or algorithm step by step, and justify the result. State units and conventions whenever a question supplies them.
