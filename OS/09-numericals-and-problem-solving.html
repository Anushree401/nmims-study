Type 1: CPU Scheduling Algorithms

FCFS · SJF · SRTF · Priority (Preemptive) · Round Robin
How to recognize: Table of processes with Arrival Time (AT), Burst Time (BT), optionally Priority or Time Quantum. Asked for Gantt chart, CT, TAT, WT, RT and averages.
Key formulas (memorize): $TAT = CT - AT$  |  $WT = TAT - BT$  |  $RT = \text{First CPU start} - AT$

Type 2: Banker's Algorithm — Safety Test & Resource Request

Need Matrix · Work Vector · Safe Sequence · Request Evaluation
How to recognize: Table of Allocation and Max for multiple processes and resources, plus Available vector. Find Need matrix, check safety, evaluate a specific request.
Key formulas: $\text{Need}[i] = \text{Max}[i] - \text{Alloc}[i]$  |  Safe if $\text{Need}[i] \le \text{Work}$ for some process, then $\text{Work} \mathrel{+}= \text{Alloc}[i]$
PYQ — Nov 2025 Final Q3(a)

Archetype 3.1 — All Three Strategies Side-by-Side

Intermediate

Archetype 5.1 — EAT with 1-Level and 2-Level Paging

5–10 marks
Part A: Memory access time = 100 ns, TLB access time = 20 ns, TLB hit ratio = 80%. Find EAT for single-level paging.
Part B: Same system, but 2-level paging. Find EAT.
FORMULA
$$\text{EAT} = h \cdot (\text{TLB} + \text{MAT}) + (1-h) \cdot (\text{TLB} + k \cdot \text{MAT} + \text{MAT})$$ where $h$ = hit ratio, $k$ = levels of page table, MAT = memory access time.
Simplified: On hit: TLB + 1 mem access. On miss: TLB + k mem accesses (page tables) + 1 mem access (data).
PART A (1-level)
On TLB Hit: 20 + 100 = 120 ns (1 page table lookup bypassed)
On TLB Miss: 20 + 100 (page table) + 100 (data) = 220 ns
$$\text{EAT}_{\text{1-level}} = 0.80 \times 120 + 0.20 \times 220 = 96 + 44 = \mathbf{140\text{ ns}}$$
PART B (2-level)
On TLB Hit: 20 + 100 = 120 ns (same — TLB gives physical address directly)
On TLB Miss: 20 + 100 (level-1 table) + 100 (level-2 table) + 100 (data) = 320 ns
$$\text{EAT}_{\text{2-level}} = 0.80 \times 120 + 0.20 \times 320 = 96 + 64 = \mathbf{160\text{ ns}}$$
ANSWER
1-Level EAT = 140 ns  |  2-Level EAT = 160 ns
Each additional level of paging adds (1−h)×MAT to EAT.
⚠ Exam Trap 1: On TLB hit, you still need 1 memory access (for the data/instruction). Don't forget this — EAT on hit = TLB + 1×MAT, not just TLB.
⚠ Exam Trap 2: With $k$-level paging, TLB miss requires $k$ page-table accesses + 1 data access = $k+1$ total memory accesses. So TLB miss time = TLB + $(k+1)$ × MAT.

Head moves in one direction only (up), serves requests, jumps to 0 when it hits end, continues upward.
Head=53, moving up: 65, 67, 98, 122, 124, 183 → 199 → jump to 0 → 14, 37
Distance = (199-53) + (199-0) + (37-0) = 146+199+37 = 382 cylinders
SUMMARY
FCFS: 640 cylinders (worst, may swing back and forth)
SSTF: 236 cylinders (good avg, risk of starvation)
SCAN: 331 cylinders (fair, uniform response time)
C-SCAN: 382 cylinders (uniform wait, biased toward far-end requests)
⚠ Exam Trap 1 (SCAN vs LOOK): SCAN goes all the way to end of disk (0 or max). LOOK only goes to the last request in that direction — does NOT go to 0 or 199. LOOK is more efficient.
⚠ Exam Trap 2 (C-SCAN jump): The jump from 199→0 in C-SCAN counts as seek distance (199 cylinders). Some papers omit this — clarify in your answer.
⚠ Exam Trap 3: SSTF can cause starvation of far-away requests if many nearby requests keep arriving.

Archetype 7.1 — Computing Max File Size with n-Level Indirection

10 marks
A UNIX file system has: Block size = 4 KB, Pointer size = 4 bytes. Each inode has: 10 direct pointers, 1 single-indirect, 1 double-indirect, 1 triple-indirect. Find maximum file size.
FORMULA
$$K = \frac{\text{Block size}}{\text{Pointer size}} = \frac{4096}{4} = \mathbf{1024 \text{ pointers/block}}$$
SectionFormulaBlocks addressableSize
Direct (10 pointers)$10 \times 1$10$10 \times 4\text{ KB} = 40\text{ KB}$
Single Indirect$1 \times K$$1024$$1024 \times 4\text{ KB} = 4\text{ MB}$
Double Indirect$1 \times K^2$$1024^2 = 1{,}048{,}576$$\approx 4\text{ GB}$
Triple Indirect$1 \times K^3$$1024^3 = 1{,}073{,}741{,}824$$\approx 4\text{ TB}$
$$\text{Max File Size} = (10 + 1024 + 1024^2 + 1024^3) \times 4\text{ KB}$$ $$\approx (10 + 1024 + 1{,}048{,}576 + 1{,}073{,}741{,}824) \times 4096 \approx \mathbf{4\text{ TB}}$$
VARIATION

What if pointer size = 8 bytes? $K = 4096/8 = 512$ pointers/block. Triple indirect = $512^3$ blocks = much smaller. Max ≈ $512 \times 512 \times 512 \times 4\text{ KB} \approx 512\text{ GB}$.

What if block size = 1 KB, pointer = 4 bytes? $K = 1024/4 = 256$. Max ≈ $256^3 \times 1\text{ KB} \approx 16\text{ GB}$.

ANSWER
With 4KB blocks, 4-byte pointers, 10+1+1+1 inode structure: Max File Size ≈ 4 TB (dominated by triple-indirect).
⚠ Exam Trap 1: $K = \text{block size}/\text{pointer size}$ — in bytes! If block = 4 KB = 4096 bytes and pointer = 4 bytes, $K = 1024$. Don't use 4/4=1.
⚠ Exam Trap 2: Max file size is dominated by triple-indirect. The direct blocks contribute negligibly — but still include them in the formula.
⚠ Exam Trap 3: Total max = sum of ALL sections (direct + single + double + triple), not just the largest one.

Archetype 8.1 — Identify & Fix Semaphore Bugs in Producer-Consumer

5 marks
A student writes the following Producer-Consumer code. Identify the mistakes and correct them.
BUGGY CODE
semaphore full = 0, empty = N, mutex = 1; Producer() { while (true) { produce_item(x); wait(full); // BUG 1: should be wait(empty) wait(mutex); insert(x); signal(mutex); signal(empty); // BUG 2: should be signal(full) } } Consumer() { while (true) { wait(empty); // BUG 3: should be wait(full) wait(mutex); remove(x); signal(mutex); signal(full); // BUG 4: should be signal(empty) consume_item(x); } }
ANALYSIS

Semaphore semantics in this problem:

  • empty = number of empty slots in buffer (init N). Producer must wait for an empty slot before inserting.
  • full = number of full slots (init 0). Consumer must wait for a full slot before removing.
  • mutex = mutual exclusion lock for buffer access (init 1).

Bug 1: Producer calls wait(full) — this waits until buffer has a full slot, which blocks forever when buffer is empty! Producer should call wait(empty) (wait for an empty slot).

Bug 2: Producer signals empty after inserting — signals that more empty slots exist, opposite of what happened (it filled a slot). Should signal full.

Bug 3: Consumer calls wait(empty) — waits for empty slots, which is what the Producer needs! Should call wait(full).

Bug 4: Consumer signals full after removing — signals more full slots, but it just removed one (created an empty slot). Should signal empty.

CORRECTED CODE
semaphore full = 0, empty = N, mutex = 1; Producer() { while (true) { produce_item(x); wait(empty); // Wait for an empty slot wait(mutex); // Enter critical section insert(x); signal(mutex); // Leave critical section signal(full); // Signal: one more full slot available } } Consumer() { while (true) { wait(full); // Wait for a full slot wait(mutex); // Enter critical section remove(x); signal(mutex); // Leave critical section signal(empty); // Signal: one more empty slot available consume_item(x); } }

4 bugs fixed: Producer: wait(empty)→signal(full). Consumer: wait(full)→signal(empty).

⚠ Exam Trap 1: There is also a potential deadlock if mutex is acquired BEFORE empty/full. If Producer holds mutex and calls wait(full/empty) which blocks, Consumer cannot acquire mutex either — deadlock! Always wait(semaphore) BEFORE wait(mutex).
⚠ Exam Trap 2 (Critical order): Correct order is ALWAYS: wait(count_semaphore) → wait(mutex) → [CS] → signal(mutex) → signal(count_semaphore). Reversing wait(mutex) and wait(empty) can cause deadlock.

Archetype 8.2 — Readers-Writers with Counting Semaphores

10 marks
Implement the Readers-Writers problem using semaphores. Multiple readers can read simultaneously; writers need exclusive access.
VARIABLES
semaphore mutex = 1; // Protects readcount semaphore wrt = 1; // Writer mutex (also used by 1st/last reader) int readcount = 0; // Number of active readers
WRITER
Writer() { do { wait(wrt); // Exclusive access // ... write ... signal(wrt); // Release } while(TRUE); }
READER
Reader() { do { wait(mutex); // Lock readcount readcount++; if (readcount == 1) wait(wrt); // First reader locks out writers signal(mutex); // Unlock readcount // ... read ... wait(mutex); // Lock readcount readcount--; if (readcount == 0) signal(wrt); // Last reader releases writer lock signal(mutex); // Unlock readcount } while(TRUE); }

Key insight: First reader acquires wrt (blocks writers). Last reader releases wrt (allows writers in). All intermediate readers can read concurrently.

⚠ Exam Trap — Writer Starvation: This first-readers-preference solution can starve writers if readers keep arriving. As long as readcount > 0, the writer never gets wrt. To solve this: add a semaphore to prevent new readers from entering when a writer is waiting (second readers-writers problem).

What to Know for the Exam

  • CPU Scheduling: Always draw Gantt chart first, derive CT from it, then compute TAT, WT, RT. Verify: Avg WT = Avg TAT – Avg BT.
  • Banker's: Three-step test — Need≤Work? Grant pretend-alloc, run safety. If unsafe, deny & rollback.
  • Memory fitting: Best-Fit = minimum leftover. First-Fit = fastest (stops at first fit). Worst-Fit = maximum leftover (leaves large holes).
  • Page replacement: State all three algorithms. FIFO can suffer Belady's anomaly. Optimal = fewest faults (unrealizable). LRU ≈ practical optimal.
  • TLB EAT: k extra memory accesses per miss for k-level page table. Hit = TLB + 1 mem access regardless of levels.
  • Disk scheduling: SSTF best seek but starves. SCAN/LOOK fair. C-SCAN uniform wait. FCFS simple but worst seek.
  • Semaphores: wait(count) BEFORE wait(mutex) or deadlock. match every wait with a signal.
