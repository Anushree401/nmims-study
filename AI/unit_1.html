1. In-depth theory explanation

Related: worked examples · comparative studies · case studies

Unit map

  • AI can be studied as systems that think or act, judged either by resemblance to human behavior or by rational performance.
  • This unit centers on the rational-agent view: an agent perceives, selects actions, and aims to maximize a stated performance measure.

1. What is AI? Four approaches

  • Artificial intelligence studies computational systems able to perform tasks that normally require capabilities such as perception, reasoning, learning, planning, language, and action. “Intelligent”
  • is not one single test;
  • the classical framework separates two dimensions:
ApproachWhat counts as successExample / limitation
Acting humanlyBehavior is indistinguishable from a human in the chosen setting.Turing Test: a text-only interrogator cannot reliably distinguish machine from human. Requires language, representation, reasoning and learning; a test can reward imitation without proving understanding.
Thinking humanlyInternal processes resemble human cognition.Cognitive modeling uses psychology/neuroscience evidence; matching the answer alone is insufficient if the reasoning process differs.
Thinking rationallyReasoning follows valid logical principles.Laws-of-thought approach, e.g. “All humans are mortal; Socrates is human; therefore Socrates is mortal.” Pure logic struggles with incomplete information, uncertainty, time and computational cost.
Acting rationallyChoose action expected to maximize performance given evidence and capabilities.Rational agent approach accommodates uncertainty and imperfect information; rational does not mean omniscient or always successful.
  • Exam point: Human-like performance and rational performance are different criteria.
  • Rationality is judged relative to evidence available when acting, not hindsight.

2. Agent, rationality and PEAS

  • An agent perceives its environment through sensors and acts on it through actuators.
  • An agent function maps percept sequences to actions; the agent program implements that function on an architecture.
  • Thus Agent = Architecture + Program.
  • Whether an action is rational depends on (1) performance measure, (2) prior knowledge, (3) available actions, and (4) percept sequence so far.
  • Rationality means selecting the action expected to maximize performance on this evidence; it does not imply perfect knowledge.
  • PEAS specifies a task environment: Performance measure, Environment, Actuators, Sensors.
  • Example: autonomous taxi — safe/legal/comfortable trip and low cost; roads, traffic, passengers and weather; steering, brakes, accelerator, indicators; cameras, GPS, lidar/radar, speedometer and microphones.

Lesson A · What are we trying to make a machine do?

  • Start with a task, not with the word “intelligence.” A machine receives information, represents something about the situation, chooses among possible actions, and produces an outcome.
  • AI studies how to make these steps work for tasks where a fixed list of simple instructions is not enough: recognizing a spoken request, planning a route, diagnosing a fault, or controlling a robot.
  • There are two independent questions in the classical definitions.
  • First: do we judge the system by its thinking or its behavior?
  • Second: do we judge it by resemblance to humans or by rational correctness?
  • Combining them gives the four approaches from the slides.
  • A human imitator may copy human mistakes; a logic system may reason correctly but be too slow to act; a rational agent instead asks which action best serves its stated objective with the evidence it has.
  • Modeling is the act of representing relevant parts of the world in a form a program can use.
  • A map is a model of road connectivity; a neural network is a learned model of relationships in examples; a rule base models expert knowledge.
  • Inference uses a model plus evidence to derive a conclusion.
  • For example, a route planner models roads and costs, then infers that one route is cheapest.
  • Learning changes the model or decision process using experience.
  • If observed travel times repeatedly exceed estimates, a learned model can update the expected road costs.
  • The three are connected, not interchangeable: learning may build the model, inference uses it, and outcomes provide new learning evidence.

Machine learning and deep learning are nested ideas

  • Machine learning uses examples or feedback to fit a model instead of specifying every output by hand.
  • In supervised learning, examples have target labels; in unsupervised learning, the system looks for structure without given labels; reinforcement learning uses rewards from actions.
  • Deep learning is a subset of machine learning that learns with neural networks containing multiple processing layers.
  • More layers can learn useful representations from raw data, but training can demand substantial data and computation. “Deep” describes network depth; it does not mean the system understands like a human.

Lesson B · From a sensor reading to an action

  • Imagine a robot vacuum at a doorway.
  • Its sensor reports “dirty.” The actuator controls a suction motor.
  • A rule can map this percept to “vacuum.” This is an agent: it observes through sensors and affects its environment through actuators.
  • The same structure applies to software agents: a web service receives inputs and emits actions through APIs.
  • An agent program runs on an architecture (hardware or software platform).
  • Its abstract agent function maps the entire percept history to an action.
  • Two programs may receive the same current percept but act differently because one remembers what happened earlier.
  • A rational agent chooses the action expected to maximize the performance measure, given percept history, prior knowledge, and available actions.
  • This is a fair-time decision rule: an action is judged by information available before the outcome, not by hindsight.

PEAS worked through carefully: autonomous taxi

  1. Performance: reach the requested destination safely and legally, minimize time and operating cost, preserve passenger comfort. These criteria may conflict; a utility function or priority hierarchy makes the trade-off explicit.
  2. Environment: roads, lanes, pedestrians, other vehicles, traffic lights, weather, passenger and destination.
  3. Actuators: steering, throttle, brakes, signals, display/speaker.
  4. Sensors: cameras, radar/lidar, GPS, wheel-speed and inertial sensors, microphone.
  5. Task properties: partially observable (occlusions and hidden intentions), multi-agent, stochastic from the agent’s view, sequential, dynamic, continuous.
  6. Architecture implication: maintain an internal state/map, predict other road users, plan, act, and update from new sensor evidence. A simple reflex “if obstacle, brake” is useful but cannot by itself handle route choice and long-term consequences.
  • For a vacuum cleaner the PEAS differs: cleanliness and low energy; rooms and furniture; wheels and suction; dirt, bump, location and battery sensors.
  • If only the current square is sensed, the agent must remember visited locations or risk wandering.
  • This is why partial observability motivates model-based agents.

Why there are several agent designs

  • A simple reflex agent applies condition–action rules to the current percept.
  • A model-based reflex agent additionally updates an internal state from the current percept and previous state.
  • A goal-based agent searches possible action sequences and asks whether they reach a goal.
  • A utility-based agent ranks goal-reaching outcomes when one is safer, cheaper, or faster than another.
  • A learning agent has a performance element that acts, a critic that evaluates results, a learning element that improves behavior, and a problem generator that encourages useful exploration.
  • Each added capability costs computation and design effort; choose it when the task needs it.

2. Worked numerical examples

NUMERICAL WORKING · GIVEN → FORMULA / RULE → STEPS → FINAL ANSWEREvery example is separated into supplied data, method, numbered working and a checked result.

Unit 1 has no arithmetic method in the slides. These practice problems apply rational-agent reasoning: state the performance measure, calculate expected outcomes, and choose the action that maximizes it.

SIMPLE NUMERICAL Expected score for one action

GIVEN
  • Success probability = 0.8; success score = 10.
  • Failure probability = 0.2; failure score = 0.
FORMULA / RULE
Expected score = Σ probability × score.
STEPWISE WORKING
  1. Success contribution = 0.8 × 10 = 8.
  2. Failure contribution = 0.2 × 0 = 0.
  3. Add the contributions: 8 + 0 = 8.
FINAL ANSWER
Expected score = 8. The agent uses this value to compare actions. See rationality.

MEDIUM NUMERICAL Choose between two delivery routes

GIVEN
  • Fast route: success p=0.80, score +100; failure p=0.20, score −40.
  • Safe route: success p=0.95, score +70; failure p=0.05, score −40.
FORMULA / RULE
EU(action) = Σ p(outcome) × performance(outcome).
STEPWISE WORKING
  1. Fast = 0.80(100) + 0.20(−40).
  2. Safe = 0.95(70) + 0.05(−40).
FINAL ANSWER
Choose the fast route, because 72 > 64.5. If the failure penalty changes, recompute both actions. See taxi-agent case.

COMPLEX NUMERICAL Compare options with different risk profiles

GIVEN
  • Action A: 0.70 chance of +120, 0.20 chance of +20, 0.10 chance of −250.
  • Action B: 0.94 chance of +85, 0.06 chance of −40.
FORMULA / RULE
EU(action) = Σ pᵢuᵢ; check that probabilities for each action sum to 1.
STEPWISE WORKING
  1. Check A probabilities: 0.70 + 0.20 + 0.10 = 1.00.
  2. EU(A) = 0.70(120) + 0.20(20) + 0.10(−250).
  3. EU(A) = 84 + 4 − 25 = 63.
  4. Check B probabilities: 0.94 + 0.06 = 1.00.
  5. EU(B) = 0.94(85) + 0.06(−40) = 79.9 − 2.4 = 77.5.
  6. Choose the larger expected utility; rationality is relative to the specified performance measure.
FINAL ANSWER
Choose Action B. This result depends on the stated score and probabilities. See goal-based vs utility-based agents.

4. Case studies and real-life examples

4. Application examples and case analysis

  • Vacuum agent: performance may reward clean squares and penalize time/energy; environment is rooms; actuators move/suck; sensors detect location and dirt.
  • If it has only a local dirt sensor, it is partially observable.
  • A fixed “if dirty, suck; otherwise move” rule is simple reflex; a map and memory make it model-based.
  • Recommendation system: observes clicks/ratings, predicts preferences, and ranks items.
  • It learns from past behavior, but the performance measure (clicks, satisfaction, diversity) changes what “good” means.
  • This is an example of modeling data and learning a policy; inference estimates likely preferences from evidence.
  • Robot arm: camera/force sensors provide percepts, actuators move joints, and a goal-based controller plans a grasp.
  • Inference derives object position; learning can improve grasp parameters.
  • The diagram and PEAS terms above provide the answer framework.
  • Applications in the deck include game playing, planning and scheduling, autonomous control, diagnosis, robotics, and logistics.
  • Describe for each: input/percepts → representation/model → decision or plan → action → performance feedback.

5. Possible exam questions

7. Likely exam questions

  1. Explain the four approaches to defining AI, with examples and limitations.
  2. Define an intelligent agent and explain rationality and its four determinants.
  3. Describe PEAS with a suitable autonomous taxi or vacuum-cleaner example.
  4. Explain task-environment properties and classify chess/taxi/vacuum.
  5. Compare simple reflex, model-based, goal-based, utility-based and learning agents.
  6. Explain the Turing Test and capabilities required to pass it.
  7. Distinguish modeling, inference, machine learning and deep learning.
  8. For 8–10 marks, draw and explain the agent–environment loop and connect it to a real application.
Answer length plan: 4 marks = definition + 3–4 points + tiny example. 6 = add diagram/PEAS. 8 = explain operation and compare alternatives. 10 = include assumptions, limitations, real case and conclusion.

Lesson C · How to build an answer that earns marks

  • For any agent question, proceed in a stable order: define agent and environment; state the performance measure; list PEAS; classify observability, determinism, time relation, dynamics, discreteness and number of agents; choose an architecture; explain how percepts produce actions; name one limitation.
  • A diagram should show arrows in both directions—percepts enter, actions leave—and label sensors and actuators.
  • For a comparison question, define both terms before listing differences and give one task where each is suitable.
  • Short practice: A board-game system sees all pieces, takes turns against another player, and uses discrete legal moves.
  • It is fully observable, multi-agent, sequential and discrete.
  • If the opponent’s move is governed by fixed rules, transitions may be deterministic, but the agent still cannot know which choice the opponent will make in advance.
  • That distinction between deterministic rules and uncertain behavior is often tested.
