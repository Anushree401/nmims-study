1.1 Formal Problem Formulation (The 4 Core Components)

In classical AI, a problem is formally defined as a collection of four mathematical components that define a State Space:

The 4 Formal Components of a Problem:

  1. Initial State \(s_0\): The state the agent starts in (e.g., in the 8-puzzle, the scrambled starting tile arrangement).
  2. Successor Function \(\text{Successor}(s)\): A transition function returning a set of ordered pairs \(\langle \text{action}, \text{result\_state} \rangle\) denoting legal actions from current state \(s\).
  3. Goal Test \(\text{Goal-Test}(s)\): A boolean function returning True if state \(s\) matches the goal configuration, or an explicit test condition.
  4. Path Cost Function \(c(s, a, s')\): A function that assigns a numeric cost to taking action \(a\) from state \(s\) to reach state \(s'\). The step costs sum up to the total path cost \(g(n)\).

The 8-Puzzle Problem Formulation:

The 8-puzzle consists of a \(3 \times 3\) grid with 8 numbered sliding tiles and one empty space (blank). A tile adjacent to the blank space can slide into the blank.

  • States: Any configuration of the 8 tiles and 1 blank across the 9 cells (Total state space: \(\frac{9!}{2} = 181,440\) reachable states).
  • Initial State: Any specified scrambled configuration.
  • Successor Function: Move blank {Left, Right, Up, Down}.
  • Goal Test: Matches the standard numerical ordering: tiles 1 to 8 sorted with blank at top-left or bottom-right.
  • Path Cost: Each tile move costs 1 unit (path cost equals total moves).

1.2 The Four Search Algorithm Evaluation Criteria

Search algorithms are evaluated based on four fundamental performance criteria parameterized by: $$\mathbf{b} = \text{Branching factor (maximum successors of any node)}, \quad \mathbf{d} = \text{Depth of shallowest goal node}, \quad \mathbf{m} = \text{Maximum depth of state space}$$

  1. Completeness: Is the algorithm guaranteed to find a solution when one exists?
  2. Optimality: Does the strategy find the lowest path cost solution among all possible solutions?
  3. Time Complexity: How many nodes are generated or expanded before finding a solution?
  4. Space Complexity: How much maximum memory is required in the frontier / explored set during search?

1.3 Uninformed (Blind) Search Strategies

Uninformed search algorithms have no information about how close a given state is to the goal. They can only distinguish between goal and non-goal states.

1. Breadth-First Search (BFS):

  • Mechanism: Expands shallowest unexpanded node first. Implemented using a FIFO Queue (First-In, First-Out).
  • Properties:
    • Complete: Yes (if \(b\) is finite).
    • Optimal: Yes (if all step costs are equal or non-decreasing).
    • Time Complexity: \(O(b^d)\).
    • Space Complexity: \(O(b^d)\) — Major Bottleneck! Memory exhausts long before CPU time.

2. Depth-First Search (DFS):

  • Mechanism: Expands deepest unexpanded node first. Implemented using a LIFO Queue / Stack or recursion.
  • Properties:
    • Complete: No (fails in infinite state spaces or graph loops without cycle checks).
    • Optimal: No (may return a deep path when a shallow goal exists).
    • Time Complexity: \(O(b^m)\) (terrible if \(m \gg d\)).
    • Space Complexity: \(O(b \cdot m)\) — Linear memory! Highly space-efficient.

3. Uniform Cost Search (UCS / Dijkstra's Algorithm):

  • Mechanism: Expands node with lowest cumulative path cost \(g(n)\). Implemented using a Priority Queue ordered by \(g(n)\).
  • Properties: Complete and optimal for any positive step costs (\(c \ge \epsilon > 0\)). Time and space: \(O(b^{1 + \lfloor C^* / \epsilon \rfloor})\).

1.4 Informed (Heuristic) Search: Greedy & A*

Informed search uses domain-specific knowledge via a Heuristic Function \(h(n)\): an estimated cost of the cheapest path from node \(n\) to a goal state (\(h(\text{goal}) = 0\)).

1. Greedy Best-First Search:

Expands the node that appears closest to the goal using evaluation function \(f(n) = h(n)\). Not optimal and not complete in graph loops, as it is susceptible to false leads.

2. A* Search (The Industry Standard):

Combines path cost so far \(g(n)\) with estimated future cost \(h(n)\):

$$\mathbf{f(n) = g(n) + h(n)}$$
  • \(g(n)\): Exact cost incurred from the start state to reach node \(n\).
  • \(h(n)\): Estimated cost from node \(n\) to the nearest goal state.
  • \(f(n)\): Estimated total cost of cheapest solution path passing through node \(n\).

Heuristic Conditions for Optimality in A*:

  • Admissibility (for Tree Search): A heuristic \(h(n)\) is admissible if it never overestimates the true cost to reach the goal: $$h(n) \le h^*(n) \quad \forall n, \quad \text{where } h^*(n) \text{ is true optimal cost.}$$
  • Consistency / Monotonicity (for Graph Search): For every node \(n\) and successor \(n'\) generated by action \(a\): $$h(n) \le c(n, a, n') + h(n')$$ Theorem: If \(h(n)\) is consistent, A* graph search is guaranteed to be optimal and never reopens closed nodes.

1.5 Local Search & Hill Climbing Pitfalls

In optimization problems where the path is irrelevant and only the final state matters (e.g., 8-Queens, VLSI layout, TSP), Local Search operates using a single current state, moving only to neighbors.

Hill Climbing (Greedy Local Search):

Continually moves in the direction of increasing value / decreasing cost. Terminates when no neighbor has a better value.

Figure 2.2: The primary state-space landscape pitfalls in Hill Climbing search.

The 3 Major Pitfalls:

  1. Local Maxima: A peak that is higher than all its neighboring states, but lower than the global maximum. The algorithm terminates prematurely thinking it has succeeded.
  2. Plateau / Shoulders: A flat area of the state space where all neighboring states have identical evaluation values. The gradient is zero, causing the search to wander aimlessly in a random walk.
  3. Ridges: A sequence of local maxima joined by steep slopes. Steep sides make navigation difficult because uphill movements require zig-zagging.

1.6 Genetic Algorithms (GA)

Genetic Algorithms are stochastic local beam search algorithms inspired by Darwinian natural selection:

  • Representation: A state is represented as a string or chromosome over a finite alphabet (typically a bit string of 0s and 1s).
  • Fitness Function: A mathematical evaluation scoring each individual's suitability (higher fitness = higher survival probability).
  • Core Operators:
    1. Selection: Proportionate roulette-wheel selection where probability of selection is \(P(i) = \frac{\text{fitness}(i)}{\sum \text{fitness}}\).
    2. Crossover: Mating two high-fitness parents by splitting chromosomes at a random crossover point and exchanging segments.
    3. Mutation: Randomly flipping individual bits with a small independent probability (e.g., \(0.01\)) to restore lost genetic diversity.

1.7 Adversarial Search: Minimax & Alpha-Beta Pruning

In two-player, competitive, zero-sum, perfect information games (Chess, Checkers, Tic-Tac-Toe), two agents with opposing utility functions play against each other: MAX seeks to maximize utility, while MIN seeks to minimize utility.

The Minimax Decision Rule

$$\text{Minimax}(s) = \begin{cases} \text{Utility}(s) & \text{if } s \text{ is Terminal} \\ \max_{a} \text{Minimax}(\text{Result}(s, a)) & \text{if } \text{Player}(s) = \text{MAX} \\ \min_{a} \text{Minimax}(\text{Result}(s, a)) & \text{if } \text{Player}(s) = \text{MIN} \end{cases}$$

Alpha-Beta (\(\alpha\)-\(\beta\)) Pruning:

Standard Minimax has an exponential time complexity of \(O(b^m)\), rendering it unusable for deep game trees. Alpha-Beta pruning returns the exact same move as Minimax while pruning away entire branches that cannot possibly influence the final decision.

  • \(\alpha\) = The highest-value choice found so far along the path for MAX (initialized to \(-\infty\)).
  • \(\beta\) = The lowest-value choice found so far along the path for MIN (initialized to \(+\infty\)).
  • Pruning Condition: Prune search below current node as soon as: $$\mathbf{\alpha \ge \beta}$$

2. In-Depth Numerical Explanations (Step-by-Step)

3 Tiered Solved Problems
Simple Example

Problem 2.1: BFS vs. DFS State Space Traversal Trace

Problem Statement: Consider a search tree rooted at node \(A\): $$\text{Children of } A: [B, C], \quad \text{Children of } B: [D, E], \quad \text{Children of } C: [F, G]$$ Goal node is \(G\). Assuming ties are broken alphabetically (left-to-right), determine: (1) The node visitation sequence for Breadth-First Search (BFS), and (2) The node visitation sequence for Depth-First Search (DFS).

BFS TRACE

BFS uses a FIFO Queue:

  1. Start: Queue \(= [A]\). Pop \(A\), expand: Queue \(= [B, C]\). Visited: A.
  2. Pop \(B\), expand: Queue \(= [C, D, E]\). Visited: B.
  3. Pop \(C\), expand: Queue \(= [D, E, F, G]\). Visited: C.
  4. Pop \(D\), leaf. Visited: D.
  5. Pop \(E\), leaf. Visited: E.
  6. Pop \(F\), leaf. Visited: F.
  7. Pop \(G\): Goal reached! Stop search.

BFS Order: A → B → C → D → E → F → G (7 nodes visited).

DFS TRACE

DFS uses a LIFO Stack:

  1. Start: Stack \(= [A]\). Pop \(A\), push right-to-left: Stack \(= [B, C]\). Visited: A.
  2. Pop \(B\), push children: Stack \(= [D, E, C]\). Visited: B.
  3. Pop \(D\), leaf. Visited: D.
  4. Pop \(E\), leaf. Visited: E.
  5. Pop \(C\), push children: Stack \(= [F, G]\). Visited: C.
  6. Pop \(F\), leaf. Visited: F.
  7. Pop \(G\): Goal reached! Stop search.

DFS Order: A → B → D → E → C → F → G (7 nodes visited).

FINAL ANSWER

BFS Path: A → B → C → D → E → F → G (Level-by-level exploration)

DFS Path: A → B → D → E → C → F → G (Deepest-first exploration)

  • Heuristics: \(h(S) = 7, h(A) = 6, h(B) = 4, h(C) = 2, h(G) = 0\).

Trace the A* algorithm execution step-by-step using priority queue ordering \(f(n) = g(n) + h(n)\). State the optimal path and total path cost.

Complex Example

Problem 2.3: 3-Ply Minimax Game Tree with Alpha-Beta Pruning

Problem Statement: A two-player zero-sum game tree has root node \(A\) (MAX). MAX has two children \(B\) and \(C\) (MIN nodes):

  • Node \(B\) has children \(D\) and \(E\) (MAX nodes).
    • Node \(D\) has static leaf utilities: \([3, 5]\).
    • Node \(E\) has static leaf utilities: \([6, 9]\).
  • Node \(C\) has children \(F\) and \(G\) (MAX nodes).
    • Node \(F\) has static leaf utilities: \([1, 2]\).
    • Node \(G\) has static leaf utilities: \([0, 8]\).

Assuming left-to-right tree evaluation, trace the Alpha-Beta pruning execution showing \([\alpha, \beta]\) bounds at every step, identify pruned branches, and state the backed-up Minimax value at root \(A\).

STEPWISE TRACE
  1. Root A (MAX): \(\alpha = -\infty, \beta = +\infty\). Calls child \(B\).
  2. Node B (MIN): Inherits \(\alpha = -\infty, \beta = +\infty\). Calls child \(D\).
  3. Node D (MAX):
    • Inspects leaf 3 → \(\alpha = \max(-\infty, 3) = 3\).
    • Inspects leaf 5 → \(\alpha = \max(3, 5) = 5\). Returns 5 to \(B\).
  4. Back to Node B (MIN):

    \(\beta = \min(+\infty, 5) = 5\). Now \([\alpha = -\infty, \beta = 5]\). Calls child \(E\).

  5. Node E (MAX):
    • Inherits \(\alpha = -\infty, \beta = 5\).
    • Inspects first leaf 6 → \(\alpha = \max(-\infty, 6) = 6\).
    • PRUNING CHECK: We now have \(\alpha = 6\) and \(\beta = 5\). Since \(\alpha \ge \beta\) (\(6 \ge 5\)), Alpha Cutoff occurs!
    • Leaf 9 is PRUNED (not evaluated). Returns 6 to \(B\).
  6. Back to Node B (MIN):

    \(\beta = \min(5, 6) = 5\). Node \(B\) returns backed-up value 5 to Root \(A\).

  7. Back to Root A (MAX):

    \(\alpha = \max(-\infty, 5) = 5\). Now at Root: \([\alpha = 5, \beta = +\infty]\). Calls child \(C\).

  8. Node C (MIN):

    Inherits \(\alpha = 5, \beta = +\infty\). Calls child \(F\).

  9. Node F (MAX):
    • Inherits \(\alpha = 5, \beta = +\infty\).
    • Inspects leaf 1 → \(\alpha = \max(5, 1) = 5\).
    • Inspects leaf 2 → \(\alpha = \max(5, 2) = 5\). Returns 2 to \(C\).
  10. Back to Node C (MIN):

    \(\beta = \min(+\infty, 2) = 2\). Now at \(C\): \(\alpha = 5, \beta = 2\).

    PRUNING CHECK: Since \(\alpha \ge \beta\) (\(5 \ge 2\)), Beta Cutoff occurs!

    Child \(G\) (and both its leaves 0 and 8) are PRUNED! Returns 2 to Root \(A\).

  11. Back to Root A (MAX):

    \(\alpha = \max(5, 2) = 5\). Root \(A\) chooses move to Node \(B\).

FINAL ANSWER

Optimal Root Minimax Value: \(\mathbf{5}\)

Optimal Decision for MAX: Move to Node \(B\)

Pruned Leaves / Subtrees: Leaf 9 (under \(E\)) and entire subtree \(G\) (leaves 0 and 8)

4. Real-World Case Studies & Practical Systems

Adversarial & Search Milestones
Adversarial Game AI Milestone

IBM Deep Blue vs. Garry Kasparov (1997)

System Genesis: In May 1997, IBM's Deep Blue became the first computer chess system to defeat a reigning world chess champion, Garry Kasparov, in a 6-game match under standard tournament time controls.

  • Search Engine Architecture: Deep Blue utilized hardware-accelerated massively parallel Minimax search with Alpha-Beta pruning, searching approximately 200 million positions per second.
  • Selective Deep Search: Utilized non-uniform depth search extending up to 40 plies deep in tactical exchanges, demonstrating the power of adversarial pruning when coupled with specialized evaluation hardware.
Navigation & Routing

Google Maps / GPS Turn-by-Turn Navigation

System Genesis: Real-time road navigation software uses hierarchical variants of A* Search (Contraction Hierarchies and Transit Node Routing) with Euclidean distance as the admissible heuristic \(h(n)\) to compute shortest paths across Continental road networks (millions of nodes) in milliseconds.

5. Possible University Exam Questions & Marking Guide

NMIMS Pattern: 4, 6, 8, 10 Marks
4 Marks

Q1. Formulate the 8-Puzzle Problem using the four components of a formal problem definition.

Marking Scheme: 1 mark per correct component (Initial state, Successor function, Goal test, Path cost).

Model Answer Key: State configuration of 8 tiles and 1 blank; Initial state: specified scrambled matrix; Successor: move blank {Left, Right, Up, Down}; Goal test: tiles in sorted order 1 to 8; Path cost: 1 per move.

6 Marks

Q2. Differentiate between BFS and DFS across the four search evaluation criteria.

Marking Scheme: 1.5 marks each for Completeness, Optimality, Time Complexity, and Space Complexity.

Model Answer Key: State completeness (BFS yes, DFS no), optimality (BFS yes for uniform costs, DFS no), time complexity (\(O(b^d)\) vs \(O(b^m)\)), and space complexity (\(O(b^d)\) exponential memory vs \(O(b \cdot m)\) linear memory).

8 Marks

Q3. Define A* Search. What is an admissible heuristic? What is a consistent heuristic? Prove why A* is optimal if h(n) is admissible.

Marking Scheme: 2 marks for \(f(n) = g(n) + h(n)\); 2 marks for admissibility condition; 2 marks for consistency; 2 marks for optimality proof outline.

Model Answer Key: Explain \(f(n) = g(n) + h(n)\). State \(h(n) \le h^*(n)\) for admissibility. State triangle inequality \(h(n) \le c(n, a, n') + h(n')\) for consistency. Outline proof: if sub-optimal goal \(G_2\) is in queue, its \(f(G_2) = g(G_2) > C^*\); any node \(n\) on optimal path has \(f(n) = g(n) + h(n) \le C^* < f(G_2)\), so \(n\) is always expanded before \(G_2\).

10 Marks

Q4. Explain the Minimax algorithm with an example. How does Alpha-Beta pruning improve Minimax? Explain the pruning conditions with a neat game tree.

Marking Scheme: 3 marks for Minimax concept and recursive formula; 3 marks for \(\alpha\) and \(\beta\) definitions; 4 marks for tree diagram illustrating \(\alpha\)-cutoff and \(\beta\)-cutoff.

Model Answer Key: Detail the Minimax decision rule. Define \(\alpha\) (best for MAX) and \(\beta\) (best for MIN). State the pruning condition \(\alpha \ge \beta\). Provide worked trace showing how branches are eliminated without altering root decision.
