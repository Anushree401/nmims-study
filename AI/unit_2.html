2.1 Problem-Solving Agents & The Solution Search Process

In Unit 1, we introduced goal-based agents. In this unit, we address how an agent actually accomplishes a goal when no immediate action presents an obvious answer: Problem Solving by Search.

A Problem-Solving Agent is a goal-based agent that decides what to do by finding sequences of actions that lead to desirable goal states.

  • Goal Formulation: The first step in problem solving. Based on the current situation and the agent's performance measure, the agent formulates a goal. A goal is defined as a set of world states in which the target objective is completely satisfied.
  • Problem Formulation: The process of deciding what actions and states to consider, given a goal. It involves abstracting away irrelevant real-world details.
  • Search: The computational process of looking for a sequence of actions that reaches a goal state. A search algorithm takes a formulated problem as input and returns a solution in the form of an action sequence.
  • Execution: Once a solution sequence is found, the agent carries out the prescribed actions one by one in the environment.

2.2 The Four Formal Components of a Problem

In your NMIMS university exams, a frequent 4-to-6 mark question asks to "Formally define a search problem with its components." Every problem is formally defined by four components:

Component Mathematical Symbol Definition & Operational Meaning 8-Puzzle Example
1. Initial State \(s_0\) The state the agent starts in within the state space. Any designated arrangement of 8 numbered tiles and 1 blank space on a 3×3 grid.
2. Successor Function (Actions + Transition Model) \(ext{SUCCESSOR}(s) o \{(a, s')\}\) Generates the legal actions executable in state $s$ and returns the resulting successor states $s'$. Moving the blank space: Left, Right, Up, or Down.
3. Goal Test \(ext{GOAL-TEST}(s) o \{ ext{True}, ext{False}\}\) Determines whether a given state matches the desired goal configuration. Can be explicit (matching a specific state) or implicit (satisfying a property). Checks whether the current board tiles exactly match the standard configuration: [Blank, 1, 2, 3, 4, 5, 6, 7, 8].
4. Path Cost \(c(s, a, s') ext{ and } g(n)\) A numeric cost function that assigns a cost to each step along a path. The path cost $g(n)$ is the sum of step costs from initial state to node $n$. Each slide move costs 1, so the total path cost equals the total number of moves in the path.

2.3 Toy Problems vs. Real-World Problems

The AI problem-solving approach distinguishes between two broad classes of problems:

  • Toy Problems: Intended to illustrate, test, or exercise various problem-solving methods. They have concise, exact mathematical descriptions that make them easy for researchers to compare algorithm benchmarks.
    • The 8-Puzzle: 3×3 board with 8 numbered sliding tiles and a blank space. State space: $9! / 2 = 181,440$ reachable states.
    • The 8-Queens Problem: Place 8 queens on an 8×8 chessboard such that no two queens attack each other (same row, column, or diagonal).
  • Real-World Problems: Problems whose solutions people actually care about in industry and life. They have messy, complex, non-standard formulations:
    • Traveling Salesperson Problem (TSP): A touring problem where a salesman must visit each of $N$ cities exactly once and return to the start city, minimizing total travel distance. NP-hard problem with $(N-1)! / 2$ tours.
    • Route Finding & Navigation: Used in Google Maps and autonomous driving networks.
    • VLSI Layout & Robot Motion Planning: Placing millions of circuit gates without wire overlaps.

2.4 Measuring Problem-Solving Performance (The 4 Evaluation Metrics)

We evaluate any search algorithm using four rigorous computational dimensions:

  1. Completeness: Is the algorithm guaranteed to find a solution when at least one solution exists in the state space?
  2. Optimality: Does the strategy find the highest quality (lowest path cost) solution among all existing valid solutions?
  3. Time Complexity: How long (or how many node expansions) does it take to find a solution? Expressed in big-O notation using branching factor $b$ and depth $d$.
  4. Space Complexity: How much memory (maximum number of nodes kept in the frontier/queue at any moment) is required?

2.5 Uninformed Search Strategies (Blind Search)

Uninformed search (also called Blind Search) means the algorithm possesses no domain-specific knowledge regarding how close a state is to the goal. It only knows how to generate successor states and test whether a state is a goal.

1. Breadth-First Search (BFS)

Expands the root node first, then expands all direct successors of the root, then their successors in turn. In general, all nodes are expanded at depth $d$ before any nodes at depth $d+1$ are touched.

  • Implementation: FIFO (First-In, First-Out) Queue. Newly generated child nodes are pushed to the tail.
  • Completeness: Yes (if branching factor $b$ is finite).
  • Optimality: Optimal if all step costs are equal (finds the shallowest goal). Non-optimal if edge costs vary.
  • Time Complexity: $O(b^d)$ — exponential.
  • Space Complexity: $O(b^d)$ — keeps every generated node in memory. Memory exhaustion is the primary failure mode of BFS.

2. Depth-First Search (DFS)

Expands the deepest unexpanded node in the current search frontier. It plunges straight down along a single branch until reaching a leaf node or goal; if a dead-end is hit, it backtracks to the next shallowest node with unexplored successors.

  • Implementation: LIFO (Last-In, First-Out) Queue / Stack, or recursive function calls.
  • Completeness: No in infinite-depth spaces or spaces with cycles (unless graph search with visited states). Yes in finite spaces.
  • Optimality: No (it returns the first solution it stumbles upon, which may be vastly deeper and costlier than a shallow optimal path).
  • Time Complexity: $O(b^m)$, where $m$ is the maximum depth. Terrible if $m \gg d$.
  • Space Complexity: $O(b \times m)$ — linear space! Only stores path from root to current node plus siblings. This is the massive advantage of DFS over BFS.

3. Uniform Cost Search (UCS)

While BFS finds the shallowest path, the shallowest path is not necessarily the cheapest path when edge costs vary. Uniform Cost Search expands the node with the lowest cumulative path cost $g(n)$ first.

  • Implementation: Priority Queue ordered by $g(n)$ (cumulative cost from start).
  • Equivalence: UCS is identical to Dijkstra's algorithm. When all step costs are equal, UCS behaves exactly like BFS.
  • Completeness & Optimality: Complete and Optimal provided every step cost is strictly positive: $c(s, a, s') \ge \epsilon > 0$.

2.6 Informed (Heuristic) Search Strategies

Unlike blind search, informed search uses problem-specific knowledge beyond the problem definition itself. This knowledge is supplied via a Heuristic Function, denoted \(h(n)\):

Heuristic Function:
\(h(n) = ext{estimated cost of the cheapest path from node } n ext{ to a goal state.}\)
If $n$ is a goal node, then $h(n) = 0$.
  • 8-Puzzle Heuristics:
    1. \(h_1(n)\): The number of misplaced tiles relative to the goal state.
    2. \(h_2(n)\): Manhattan Distance — the sum of horizontal and vertical distances of each tile from its target position.
  • Admissible Heuristic: A heuristic $h(n)$ is admissible if it never overestimates the true cost to reach the goal. That is, \(h(n) \le h^*(n)\), where $h^*(n)$ is the true optimal cost. Admissible heuristics are optimistic.

2.7 Greedy Best-First Search vs. A* Search

1. Greedy Best-First Search

Evaluates nodes using solely the heuristic function: \(f(n) = h(n)\). It greedily expands the node that appears to be closest to the goal.

Fatal Flaw: It completely ignores the accumulated path cost $g(n)$ from the start. Like DFS, it can be led down an arbitrarily expensive or false path. It is neither complete nor optimal.

2. A* Search (The King of Heuristic Search)

A* combines the proven optimality of Uniform Cost Search with the goal-oriented velocity of Greedy Best-First Search:

Evaluation Function of A*:
\(f(n) = g(n) + h(n)\)
where:
  • \(g(n)\) = exact path cost from initial start state to current node $n$.
  • \(h(n)\) = estimated heuristic cost from node $n$ to the goal.
  • \(f(n)\) = estimated total cost of the cheapest solution passing through node $n$.

Optimality Theorem of A*: Tree-search A* is optimal if \(h(n)\) is admissible. Graph-search A* is optimal if \(h(n)\) is consistent (monotonic) (\(h(n) \le c(n, a, n') + h(n')\)).

2.8 Hill Climbing Search & The 3 Landscape Pitfalls

Hill Climbing is a local search algorithm that continuously moves in the direction of increasing elevation (heuristic value or fitness) to find the peak of a state-space landscape. It keeps only the current state in memory—it does not maintain a search tree!

  • Simple Hill Climbing: Evaluates neighbors one-by-one and greedily selects the very first neighbor that improves over the current state.
  • Steepest-Ascent Hill Climbing: Evaluates all neighboring states first, and selects the single neighbor that yields the greatest improvement.
  • Stochastic Hill Climbing: Selects a neighbor at random and accepts it based on the probability of improvement.

The Three Major Pitfalls of Hill Climbing

  1. Local Maxima: A peak that is higher than all its immediate neighbors, but significantly lower than the global maximum. The algorithm terminates prematurely thinking it has found the solution.
  2. Plateau (Flat Area): A flat region of the state space where all neighboring states possess the identical heuristic value. The algorithm has no gradient to decide which direction to move.
  3. Ridge: A sequence of local maxima joined by a narrow crest. The steep sides slope down in every orthogonal search direction, causing the algorithm to oscillate helplessly without progressing along the ridge crest.

2.9 Genetic Algorithms (GA)

A Genetic Algorithm is a global stochastic search heuristic inspired by Charles Darwin's theory of biological evolution: "Survival of the Fittest."

  • Chromosome / String Representation: A potential solution is encoded as a fixed-length character or bit string (e.g., 10100110).
  • Fitness Function: A mathematical scoring function that evaluates how well each individual string solves the optimization problem.

The Three Basic Operators of GA

  1. Selection (Reproduction): Selects the best parent chromosomes from the population based on fitness. High-fitness individuals have a higher probability of passing genetic traits to the next generation.
  2. Crossover (Recombination): The primary exploration operator. A crossover point is chosen at random within the mating pool, and string segments between two parent chromosomes are swapped to produce new child offspring.
  3. Mutation: A background operator. Flips random bits (changing 0 → 1 or 1 → 0) with a low probability. Crucial Purpose: It injects genetic diversity and prevents premature convergence into a local optimum.

2.10 Adversarial Search: Game Playing & The Minimax Algorithm

In multi-agent competitive environments, agents have conflicting goals. One player's win is the other player's loss (Zero-Sum Games). Games are formalized with 4 components:

  1. Initial State: Board position and which player's turn it is.
  2. Successor Function: Legal moves and resulting board states.
  3. Terminal State: Checks whether the game has ended (win, loss, or draw).
  4. Utility Function: Assigns numeric value to terminal states (e.g., +1 for win, -1 for loss, 0 for draw).

The Minimax Algorithm

Assuming both players play optimally, MAX wants to maximize the utility value, while MIN wants to minimize it.

Minimax Decision Rule:
\(ext{Minimax}(s) = \begin{cases} ext{Utility}(s) & ext{if } s ext{ is Terminal} \ \max_{a} ext{Minimax}( ext{Result}(s, a)) & ext{if } ext{Player}(s) = ext{MAX} \ \min_{a} ext{Minimax}( ext{Result}(s, a)) & ext{if } ext{Player}(s) = ext{MIN} \end{cases}\)

2.11 Alpha-Beta (α-β) Pruning

The problem with minimax is exponential complexity: $O(b^m)$ evaluations. Alpha-Beta Pruning is an optimal pruning technique that computes the exact identical minimax value at the root while pruning away branches that cannot possibly influence the final decision.

  • $\alpha$ (Alpha): The value of the best choice found so far along the path for MAX (initially $-\infty$).
  • $\beta$ (Beta): The value of the best choice found so far along the path for MIN (initially $+\infty$).
  • Pruning Condition: Whenever \(\alpha \ge \beta\) at any node, prune all remaining unexplored branches below that node!
    • Alpha Cut: Occurs when exploring a MIN node, if its backed-up value $\beta \le \alpha$.
    • Beta Cut: Occurs when exploring a MAX node, if its backed-up value $\alpha \ge \beta$.

SIMPLE BFS vs DFS Search Traversal Tracing

GIVEN: A binary tree with Root node 1 having children Left=2, Right=3. Node 2 has children 4, 5. Node 3 has children 6, 7. Determine the exact node expansion sequence for both BFS and DFS.
STEPWISE WORKING:
  1. Breadth-First Search (FIFO Queue):
    Initial Queue: [1].
    Pop 1 → Add 2, 3 → Queue: [2, 3].
    Pop 2 → Add 4, 5 → Queue: [3, 4, 5].
    Pop 3 → Add 6, 7 → Queue: [4, 5, 6, 7].
    Pop 4, 5, 6, 7 → Sequence: 1, 2, 3, 4, 5, 6, 7 (Level Order).
  2. Depth-First Search (LIFO Stack):
    Initial Stack: [1].
    Pop 1 → Push right child 3, left child 2 → Stack: [3, 2].
    Pop 2 → Push right child 5, left child 4 → Stack: [3, 5, 4].
    Pop 4 → Stack: [3, 5]. Pop 5 → Stack: [3].
    Pop 3 → Push 7, 6 → Pop 6, Pop 7 → Sequence: 1, 2, 4, 5, 3, 6, 7 (Pre-Order).
FINAL ANSWER: BFS traversal: 1, 2, 3, 4, 5, 6, 7 | DFS traversal: 1, 2, 4, 5, 3, 6, 7.

MEDIUM Step-by-Step A* Search Graph Trace

GIVEN: Find the shortest path from start node S to goal node G using A* search. Graph edges with step costs:
  • S → A (cost 1), S → G (cost 10)
  • A → B (cost 2), A → C (cost 1)
  • B → D (cost 5)
  • C → D (cost 3), C → G (cost 4)
  • D → G (cost 2)
Heuristic values: \(h(S)=5, h(A)=3, h(B)=4, h(C)=2, h(D)=6, h(G)=0\).
FORMULA: \(f(n) = g(n) + h(n)\). Expand node with minimum $f(n)$ from the Priority Queue (Open List).
STEPWISE TRACE:
  1. Step 1: Start at S. \(g(S)=0, h(S)=5 \implies f(S)=5\).
    Open List: [S(5)]. Closed: {}.
  2. Step 2: Expand S. Successors:
    A: \(g(A) = 0 + 1 = 1\); \(f(A) = 1 + h(A) = 1 + 3 = 4\).
    G: \(g(G) = 0 + 10 = 10\); \(f(G) = 10 + 0 = 10\).
    Open List: [A(4), G(10)]. Closed: {S}.
  3. Step 3: Expand A (lowest $f=4$). Successors:
    B: \(g(B) = 1 + 2 = 3\); \(f(B) = 3 + 4 = 7\).
    C: \(g(C) = 1 + 1 = 2\); \(f(C) = 2 + 2 = 4\).
    Open List: [C(4), B(7), G(10)]. Closed: {S, A}.
  4. Step 4: Expand C (lowest $f=4$). Successors:
    D: \(g(D) = 2 + 3 = 5\); \(f(D) = 5 + 6 = 11\).
    G: \(g(G) = 2 + 4 = 6\); \(f(G) = 6 + 0 = 6\) (updates path to G from 10 down to 6!).
    Open List: [G(6), B(7), D(11)]. Closed: {S, A, C}.
  5. Step 5: Expand G (lowest $f=6$). G is the goal node! Search terminates.
FINAL ANSWER: Optimal Path: S → A → C → G with total path cost \(g(G) = \mathbf{6}\).

COMPLEX Minimax Game Tree with Full Alpha-Beta Pruning Tracing

GIVEN: Game tree of depth 3 from Slide 55: Root A (MAX) has children B, C (MIN). B has children D, E (MAX). C has children F, G (MAX). Terminal utility values at leaf nodes:
  • D's children: [2, 3]
  • E's children: [5, 9]
  • F's children: [0, 1]
  • G's children: [7, 5]
Trace DFS alpha-beta pruning. State which nodes are evaluated, which are pruned, and the root value.
RULES: At MAX node: \(\alpha = \max(\alpha, ext{val})\). At MIN node: \(\beta = \min(\beta, ext{val})\). Prune if \(\alpha \ge \beta\).
STEPWISE TRACE:
  1. Initialize root A: \(\alpha = -\infty, \beta = +\infty\).
    Pass down to B (\(\alpha = -\infty, \beta = +\infty\)) and D (\(\alpha = -\infty, \beta = +\infty\)).
  2. Evaluate D (MAX):
    Examines first leaf 2 → \(\alpha = \max(-\infty, 2) = 2\).
    Examines second leaf 3 → \(\alpha = \max(2, 3) = 3\).
    D returns value 3 to parent B.
  3. At Node B (MIN):
    Receives 3 from D → \(\beta = \min(+\infty, 3) = 3\).
    Now at B: \(\alpha = -\infty, \beta = 3\).
  4. Explore Node E (MAX) under B:
    E inherits \(\alpha = -\infty, \beta = 3\) from B.
    Examines first leaf 5 → \(\alpha = \max(-\infty, 5) = 5\).
    Check Pruning Condition at E: \(\alpha = 5 \ge \beta = 3\)!
    PRUNE! Leaf node 9 is pruned (Beta cut). E returns 5 to B.
  5. Back to B (MIN):
    B compares \(\min(3, 5) = 3\). B returns 3 to root A.
  6. Back to Root A (MAX):
    A receives 3 from B → \(\alpha = \max(-\infty, 3) = 3\). A has \(\alpha = 3, \beta = +\infty\).
  7. Explore Node C (MIN) under A:
    C inherits \(\alpha = 3, \beta = +\infty\). Passes down to F (\(\alpha = 3, \beta = +\infty\)).
    At F (MAX): Examines leaf 0 → \(\alpha = \max(3, 0) = 3\).
    Examines leaf 1 → \(\alpha = \max(3, 1) = 3\). F returns value 1 to C.
  8. Back to C (MIN):
    Receives 1 from F → \(\beta = \min(+\infty, 1) = 1\).
    Check Pruning Condition at C: \(\alpha = 3 \ge \beta = 1\)!
    PRUNE! Entire subtree under G (leaves 7 and 5) is completely pruned (Alpha cut)!
  9. C returns 1 to root A. Root A chooses \(\max(3, 1) = \mathbf{3}\).
FINAL ANSWER: Minimax Value at Root A = 3.
Pruned Leaves: Leaf 9 under node E, and Leaves 7 and 5 under node G.
The algorithm saved 3 out of 8 leaf evaluations (37.5% reduction).
