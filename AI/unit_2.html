1. In-depth theory explanation

Related: worked examples · comparative studies · case studies

1. Problem-solving agent and search formulation

  • A problem-solving agent formulates a goal, defines a state space and searches for an action sequence.
  • A search problem specifies initial state, successor function/actions, goal test, path-cost function.
  • A solution is a path from start to a goal; an optimal solution has minimum path cost.
  • Evaluate algorithms by completeness, optimality, time and space.
  • Let b be branching factor, d shallowest solution depth, m maximum depth.

  • UCS is appropriate when step costs differ.

3. Heuristics, Greedy and A*

  • A heuristic h(n) estimates remaining cost from n to a goal.
  • It guides search but is not necessarily exact.
  • Greedy best-first uses f(n)=h(n); it can be fast but may choose an attractive dead end and is not generally optimal.
  • A* uses f(n)=g(n)+h(n), balancing cost already paid and estimated cost remaining.
  • An admissible heuristic never overestimates true remaining cost; with standard graph-search assumptions, consistency (triangle inequality) supports optimality.

5. Local search and genetic algorithms

  • Hill climbing keeps the current state and moves to a better neighbor.
  • Simple variant takes first improvement; steepest-ascent evaluates all neighbors; stochastic chooses among improving moves.
  • It uses little memory but may stop at local maxima, plateau (flat neighbors), or ridge (progress requires a sequence not directly uphill).
  • Remedies include random restart, sideways moves, simulated annealing or maintaining a population.
  • Genetic algorithm (GA): encode candidates as chromosomes; initialize population; evaluate fitness; select parents; crossover/recombine; mutate; replace population; repeat until target or budget.
  • Selection pressure promotes fit candidates; crossover combines building blocks; mutation restores diversity.
  • GA is stochastic and does not guarantee a global optimum.

Worked GA generation (maximize number of 1s)

  • Chromosomes: 1100 (fitness 2), 1011 (3), 0110 (2), 1110 (3).
  • Fitness is the count of 1 bits.
  • Select parents 1011 and 1110.
  • One-point crossover after bit 2 (10|11 and 11|10) produces 1010 (fitness 2) and 1111 (fitness 4), so crossover produces a new best.
  • Separately, flipping bit 2 of 1010 from 0 to 1 yields 1110 (fitness 3).
  • Mutation can help or hurt; selection can retain a fitter individual.
  • Stop when the target fitness or generation limit is reached.

6. Adversarial search: minimax and alpha–beta

  • Game formulation includes initial state, legal successor function, terminal test and utility.
  • In a two-player zero-sum game, MAX chooses a move to maximize utility and MIN responds to minimize it.
  • Minimax assumes both players act optimally.
  • For branching factor b and depth m, naive minimax visits O(bm) leaves; depth limits use an evaluation function.
  • Alpha–beta pruning returns the same minimax decision while avoiding branches. α = best value MAX can guarantee on path; β = best value MIN can guarantee.
  • Prune when α ≥ β.
  • Search order affects pruning amount, not final decision.

Alpha–beta worked calculation

  • Root MAX has left MIN children [3,5] and right MIN children [2,9], searched left to right.
  1. Evaluate left MIN: min(3,5)=3; root α=3.
  2. At right MIN, first leaf gives 2, so β=2.
  3. Since β(2) ≤ α(3), MAX already has a better option (3); remaining leaf 9 cannot change this MIN node’s value below 2, so prune it.
  4. Root chooses left branch with value 3. Without pruning, same decision after four leaves; with pruning only three leaves evaluated.

Lesson A · Turn a real task into a search problem

  • Search does not mean browsing the internet.
  • It means systematically exploring possible states and actions.
  • In a route task, a state can be a city, an action is taking a road, the successor function lists reachable cities, and path cost is distance or travel time.
  • A search tree records different paths; the underlying state graph can contain cycles, so practical algorithms track visited states.
  • Before selecting an algorithm, specify: initial state, actions/successor function, goal test, and path cost.
  • These choices define what “solution” and “best” mean.
  • An 8-puzzle solution is an action sequence that transforms the initial board to the target; if every slide costs 1, minimum moves is minimum cost.
  • A traveling-salesperson solution is a closed tour visiting every city once; its cost is total distance.
  • Search keeps a frontier (generated but not yet expanded nodes), often an explored set, and parent links used to reconstruct the path.
  • Completeness asks whether a solution will be found; optimality whether the returned path is least cost; time and space measure node expansions and stored nodes.
  • A search may be complete but impractical because its frontier grows exponentially.

Lesson B · Three uninformed strategies, step by step

  • Breadth-first search (BFS) uses a FIFO queue.
  • Remove the oldest node, test it, append its successors.
  • Because it expands depth 0, then depth 1, then depth 2, BFS finds the fewest-edge solution when step costs are equal.
  • Its weakness is memory: it stores many nodes at the current frontier.
  • Depth-first search (DFS) uses a stack or recursion.
  • It follows one branch until it cannot continue, then backtracks.
  • It can reach a deep solution quickly and stores roughly one path plus siblings, but may dive forever in an infinite branch and does not guarantee the cheapest solution.
  • Depth-limited search puts a cap on depth; iterative deepening repeatedly raises the cap and combines DFS-like memory with BFS-like shallow-solution completeness for equal costs.
  • Uniform-cost search (UCS) uses a priority queue ordered by accumulated cost g(n).
  • It expands the least-cost path so far.
  • With positive step costs, the first goal removed from the frontier is optimal.
  • Do not stop when a goal is merely generated: a cheaper route to that goal may still be in the frontier.

Worked comparison with a trace

  • Edges: S→A cost 2, S→B cost 1, B→A cost 0.5, A→G cost 4, B→G cost 8.
  • BFS sees paths by number of edges and may return S→A→G (two edges, cost 6) before S→B→A→G (three edges, cost 5.5).
  • UCS instead processes:

Lesson C · Heuristics, Greedy search and A*

  • A heuristic is a domain-informed estimate of cost remaining.
  • For an 8-puzzle, number of misplaced tiles is easy to compute; Manhattan distance sums each tile’s row and column distance from its goal square.
  • A useful heuristic makes informed search focus, but an inaccurate heuristic can mislead.
  • Greedy best-first ranks only h(n), as if the path already travelled were free.
  • A* ranks f(n)=g(n)+h(n).
  • The heuristic is admissible if it never overestimates the true cheapest remaining cost.
  • It is consistent if for every edge n→n′ of cost c, h(n)≤c+h(n′).
  • Consistency makes f values nondecreasing along a path and supports graph-search optimality when a state is closed.
  • With h=0, A* reduces to UCS.

A* full calculation

  • Use S→A (1), S→B (4), A→C (2), A→G (7), B→C (1), C→G (3); h(S)=5, h(A)=4, h(B)=3, h(C)=2, h(G)=0.
  1. At S, g=0. Generate A: g=1,f=1+4=5; B: g=4,f=4+3=7. Expand A.
  2. At A, generate C: g=3,f=3+2=5; G: g=8,f=8+0=8. Expand C.
  3. At C, generate G with g=6,f=6. Replace the previously found G cost 8.
  4. Pop G(6); return S→A→C→G, cost 6.
  5. Check admissibility: true remaining costs are h*(A)=5, h*(B)=4, h*(C)=3. Given estimates 4,3,2 are each no larger, so they are admissible.
  • For an exam trace, show the open list after each expansion, label each node g,h,f, update duplicate states when a cheaper path appears, and stop at the correct time.

Lesson D · Hill climbing and genetic algorithms

  • Hill climbing is local optimization: keep one current candidate and move to a neighbor with a better evaluation.
  • It does not store the full search tree.
  • A local maximum is better than every immediate neighbor but not globally best; a plateau has equal-valued neighbors; a ridge has a narrow uphill direction that single local moves do not follow.
  • Random restart tries new starting points; sideways moves cross flat regions but can loop; simulated annealing sometimes accepts a worse move to escape traps.
  • Illustration: Suppose state scores along a line are 2→5→7→6→10.
  • Starting at 2, greedy ascent reaches 7 and stops because its neighbor is 6, even though the global maximum is 10 beyond the valley.
  • A random restart at the far side could find 10.
  • This is why hill climbing is neither complete nor optimal in general.
  • Genetic algorithms search with a population.
  • A chromosome encodes a candidate; fitness scores it.
  • Selection favors stronger candidates; crossover combines parts; mutation changes a gene and maintains diversity.
  • A generation may improve the best fitness, but stochastic choices mean it is not guaranteed to improve every time.

Worked GA example: maximize number of 1 bits

  1. Population: 1100 (fitness 2), 1011 (3), 0110 (2), 1110 (3).
  2. Select 1011 and 1110 as parents (fitness is count of 1s).
  3. One-point crossover after the second bit: 10|11 and 11|10 → children 1010 and 1111.
  4. Mutate third bit of 1010 from 1 to 1? No change would teach nothing; instead mutate second bit 0→1, yielding 1110. For a mutation that creates a new best, mutate the third bit of 1010 (1→0 is worse); instead take child 1010 and flip its second bit 0→1 then its fourth bit 0→1 across two independent mutations, yielding 1111. In an exam, specify exactly which bit flips and recalculate fitness.
  5. Fitness(1111)=4, so the optimum for this toy objective is found.
  • The example illustrates representation and operators; real GA results depend on population, encoding, selection pressure, crossover/mutation rates and stopping rule.

Lesson E · Minimax and alpha–beta pruning

  • In adversarial search, each player’s outcome depends on the opponent.
  • A game tree alternates MAX and MIN levels.
  • At terminal nodes write utility from MAX’s viewpoint (win positive, loss negative); propagate upward by taking maximum at MAX and minimum at MIN.
  • This is minimax.
  • It assumes rational play by both sides and can grow exponentially with depth, so practical systems use depth cutoffs and evaluation functions.
  • Alpha–beta gives the same result while pruning branches. α is the best value MAX can already guarantee; β is the best value MIN can already guarantee.
  • Once α≥β, remaining choices at that node cannot change the final choice.
  • In the tree above, after left MIN returns 3, root α=3.
  • At right MIN, first leaf is 2, so β=2.
  • Since β≤α, the leaf 9 need not be examined: MAX will never choose a branch that MIN can hold to 2 when 3 is available.
  • Pruning effectiveness depends on move ordering.
  • Best-case ordering can reduce work dramatically (roughly from b^m to b^(m/2)); worst case may prune little.
  • It never changes the minimax decision.

4. Case studies and real-life examples

Route planning

  • A road network is a weighted graph: intersections are states, roads are actions, travel time is path cost.
  • UCS is suitable when travel costs are known; A* can use straight-line distance as an admissible heuristic when it never exceeds actual road distance.
  • Traffic makes costs time-dependent, so the model and heuristic assumptions should be stated.
  • See UCS and A* worked traces.

Travelling salesperson and game search

  • The TSP asks for a minimum-cost tour visiting each city exactly once; it demonstrates combinatorial explosion and motivates heuristics/optimization.
  • Chess illustrates adversarial search: minimax plans against an optimal opponent, while alpha–beta avoids branches that cannot affect the move.
  • The AIMA text provides the standard search/game framework: AIMA chapter outline.

5. Possible exam questions

8. Possible questions

  1. Define a search problem and explain its four elements and evaluation criteria.
  2. Compare BFS, DFS and UCS; give completeness, optimality, time and space.
  3. Compute a UCS/A* path and show frontier costs at every expansion.
  4. Explain admissibility and consistency of heuristics; why can greedy search be suboptimal?
  5. Explain hill-climbing failures and remedies.
  6. Describe GA steps and explain selection, crossover and mutation.
  7. Derive minimax values for a game tree; demonstrate alpha–beta pruning with α,β.
  8. For 10 marks, compare uninformed, informed, local and adversarial search using one application each.

Lesson F · A numerical answer checklist

  • For any search numerical, write the state graph/tree first; annotate edge costs; state the queue type or evaluation function; show frontier after every expansion; identify repeated states and updates; reconstruct the path; verify its total cost.
  • For a game tree, label MAX/MIN levels, terminal utilities, backup values, then α and β at pruning decisions.
  • For GA, show chromosome encoding, fitness, exact selection/crossover/mutation and stopping test.
  • These visible steps earn credit even if an arithmetic slip occurs.
